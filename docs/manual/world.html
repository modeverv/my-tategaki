CHAPTER 08

人物・作品設定を整理する

人物、Fact、Scene、時系列、伏線、話し方と知識差を根拠付きで管理する。

人物、場所、設定上の事実、場面、時系列、伏線を、本文の出典と一緒に管理します。作者が記録した内容とAIの候補を区別し、確認したものを採用してから推敲に使います。

登録やローカル検査はAIなしで使えます。AIで候補を抽出する場合だけ、先に AI接続を設定してください。どの操作も、設定カードの内容を原稿へ自動で書き込みません。

人物・場所・設定を登録する

  1. 作品フォルダに原稿を保存し、根拠にしたい本文の位置へ移動します。引用範囲を選択しておくと、その文章を出典として扱えます。
  2. Studioの [人物]、[原稿] → [人物・設定]、または M-x tategaki-world を開きます。
  3. [人物・設定を登録] で種類と名前を入力します。事実を記録する場合は [事実を登録] から始められます。
  4. カードの根拠とリンクを確認します。内容を直すときは [編集]、原稿上の根拠を選び直したときは [位置更新] を使います。
種類記録するもの
Character人物。
Place / Organization場所・組織。
Object / Event物・出来事。
Relationship関係や正式名と別名の対応。
Fact対象・属性・値を持つ具体的な事実。
Scene引用範囲に対する視点・登場人物・情報の共有範囲。

直接登録するコマンドは M-x tategaki-world-add です。人物カードには採用済みの別名も含めた初出と、原稿の登場箇所へのリンクを表示します。これは名前の文字列を手掛かりにした表示で、同名の別人まで自動で判別するものではありません。

本文の観察・推測・作者確認を区別する

状態意味
observed本文で観察された内容。
inferred未採用の推測・候補。AI抽出の結果はこの状態で入ります。
author-confirmed作者が登録・採用した内容。
rejected作者が却下した内容。

カードの [採用] は作者確認済みへ、[却下] は却下へ変更します。候補は、採用するまで確定した作品設定として相談に使いません。原稿が変わり候補の出典が古くなった場合は、再抽出や出典の確認を求めます。

Factで同じ条件の設定を揃える

Factには、名前に加えて対象 subject、属性 attribute、値 value、同じ時点・場面を表す context、知っている人物 known-by を記録します。

入力項目例
事実の名前駅に着いたときの鞄の色
対象花子の鞄
属性color
値青
同一時点・場面第一章・駅への到着
知っている人物花子,reader

reader は読者です。複数名はカンマで区切ります。別の場面で鞄を持ち替えたのであれば、contextも分けます。時点を区別せず両方を同じ条件へ登録すると、意図した変化も不一致の候補になります。

人物が情報を知ったことは knowledge:鍵の場所 のような属性で記録できます。AI抽出候補には、見た・聞いた・読んだ・推測などの獲得経路も保持します。登場人物がその場にいることだけで、情報を知ったとは扱いません。

別名を対応付ける

Relationship を登録し、属性を alias、対象を正式名、値を別名にします。採用した別名は人物の初出・言及の検索に使います。似た名前を自動で同じ人物へ統合する機能ではありません。

Sceneの視点と知識範囲を分ける

Sceneを登録する前に、注釈を付けたい本文の引用範囲を選びます。次の3項目は別々の意味を持ちます。

項目意味
pov視点人物。
characters登場人物。
visibility選択した引用の内容を知る人物。人物相談に引用を渡せる範囲を決めます。

例えば花子視点の場面に太郎が登場しても、花子の心中まで太郎が知るとは限りません。pov と characters から知識を推定せず、共有した情報だけを visibility に登録してください。

カードには「採用で許可する範囲」とその引用を表示します。範囲を広げるには広げた範囲そのものの正確な引用が必要です。章や明示的な場面区切りをまたいだ引用を、人物の許可範囲として使いません。

本文から候補を抽出し、確認して採用する

  1. 作品設定の画面で [選択範囲から候補抽出]、または [本文全文から候補抽出] を押します。
  2. 進捗を確認します。全文は既定5000字を目安に分け、順番に処理します。止めるときは [抽出を中止] を押します。
  3. 完了後、一覧を更新して候補の種類、属性、引用、Sceneの許可範囲を読みます。
  4. 本文の根拠が適切な候補だけ [採用] し、不要なものは [却下] します。

M-x tategaki-world-extract は選択範囲、未選択なら現在の段落を対象にします。M-x tategaki-world-extract-all は現在の原稿全文を対象にします。保存していない編集内容も、実行時の本文として扱います。

候補には処理範囲内の正確な根拠引用が必要です。モデルが勝手に返したIDや採用済み状態をそのまま保存しません。全処理が成功し、原稿とAI設定が変わっていない場合にまとめて保存します。途中で中止・失敗した場合は途中候補を保存しません。

根拠が一致することは、モデルの解釈が正しいことまで保証しません。曖昧な代名詞、比喩、嘘、推測、回想などは本文を読み直して判断してください。送信範囲と接続先の扱いは AIとプライバシーで説明します。

登録した事実の不一致を検査する

[矛盾検査] または M-x tategaki-world-check は、同じcontextにある登録Factを比較します。年齢、日付・曜日、場所、左右、色、所有、関係、呼称、生死、知識、一人称などの値が食い違う場合に候補を提示します。指摘一覧から根拠へ移動して確認します。

これは登録した事実の比較です。未登録の設定まで原稿全体から理解して、すべての矛盾を発見するものではありません。原稿上の根拠が古くなった項目も確認が必要です。位置だけを信じて変更後の文章へ飛ぶことはありません。

原稿順と作品時間を見比べる

[原稿] → [時系列]、C-c s t、または M-x tategaki-timeline で時系列を開きます。[場面を登録] で場面名と日時を入力し、[原稿順] / [作品時間順] で並べ方を切り替えます。

日時状態入力する内容
exact明示する日時。形式は YYYY-MM-DD HH:MM。
relative基準場面と、そこから何分後か。前なら負数を指定します。
inferred推測として扱う日時。
unknown日時が不明。

日時の確かさと、作者が採用したかどうかは別に管理します。相対日時は、先に基準場面を登録・採用してから扱います。基準がないものや循環して参照するものは未解決になります。不明な年を現在年で補うことはありません。

[本文全文から日時候補] または M-x tategaki-timeline-extract で、明示日時や「翌日」などの候補を抽出できます。選択範囲だけのボタンもあります。候補を読み、必要なら [編集] で基準や日時を直してから採用します。AIが原稿中の時間をすべて自動確定する機能ではありません。

伏線の配置と回収を対応付ける

[原稿] → [伏線]、C-c s f、または M-x tategaki-foreshadow で一覧を開きます。配置した箇所で [伏線を登録] を押し、名前を付けます。未回収の項目には [現在位置で回収] があり、回収場面へ移動してから使います。

AIを使う場合は [本文全文から配置・回収候補] または [選択範囲から候補] を実行します。M-x tategaki-foreshadow-extract は全文抽出です。結果は未採用の候補として表示します。

  1. 配置候補の引用を確認し、採用して未回収の伏線にします。
  2. 回収候補を採用するとき、対応する未回収の伏線を作者が選びます。
  3. 配置と回収の両方の引用、および回収位置が配置より後であることを確認します。

候補が出ただけで既存の伏線を回収済みにしません。未回収・回収済み・候補・却下を分け、採用した回収候補は対応付けの記録を残します。作品の意図として伏線かどうか、回収が十分かどうかは作者が判断します。

人物ごとの話し方を確認する

先に作品設定へ人物を登録してから、[原稿] → [人物の話し方]、C-c s v、または M-x tategaki-voice を開きます。

  1. 本文の台詞を選び、[選択台詞を見本に登録] で人物を指定します。
  2. [話し方を設定] で一人称、二人称、語尾、使わない語彙、文長、敬語の方針を入力します。語の欄を空にすると、その項目は制約なしです。
  3. [選択台詞を検査] または [原稿を検査] で、登録した規則と比較します。

台詞の見本から頻出表現も表示します。複数の句に現れる3〜12文字の反復を数え、同じ出現数なら長い表現を優先します。形態素解析ではないため、単語の途中からの候補も含まれます。登録した見本の文面は、後で原稿を変更しても例文として残ります。

普通の会話文に話者を付ける

「台詞」 の前後にある「花子は言った」「と太郎は答えた」などの描写や、登録見本の反復表現・一人称から、話者候補を示します。根拠がなければ不明、競合すれば複数候補のままです。[人物名として採用] を押した台詞だけを、その人物の見本として登録します。

採用前の候補を口調検査へ混ぜません。原稿が変わって候補が古くなったら、候補を更新してください。話し方の検査は文字列や文長などのローカル比較であり、文体の良し悪しを採点したり、入れ子の会話・引用・皮肉の本当の話者を網羅的に判定したりするものではありません。

読者と人物の知識差を確認する

原稿の確認したい位置へ移動し、[原稿] → [読者と人物の知識を比較]、C-c s k、または M-x tategaki-knowledge-compare を実行して人物を選びます。Assistantの [読者との知識差] からも開けます。

現在位置までの登録Factを「読者だけ」「人物だけ」「両方」に分け、出典リンクを表示します。Factの known-by に reader を含めると読者側の知識として扱います。記録がない情報は不明です。未登録であることから、その人物が知らないと断定しません。

人物への AI相談では、この知識注釈とSceneの許可範囲を使って本文の参照を制限します。人物の心理や認識を自動で完全に理解するものではないため、共有してよい引用範囲を作者が確認してください。

保存場所と日常の使い方

作品フォルダの .tategaki/ に、world.json、timeline.json、foreshadow.json、voice.json、voice-profiles.json を保存します。名前を付けていない原稿ではメモリ上の記録となるため、続けて使う作品は保存先を決めてから登録してください。

原稿を書き直したら、必要なカードの根拠と時点を確認します。AI抽出を毎回やり直す必要はなく、少数のFactや伏線を手で登録するところから始められます。検査をまとめて確認する入口は レビュー一覧です。補助画面を読み終えたら上部の [閉じる] で原稿へ戻れます。
