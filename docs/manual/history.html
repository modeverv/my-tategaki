CHAPTER 06

履歴・再開・読み返し

旧稿を別コピーで復元し、比較する。前回位置、Reader、音読。

保存前の文章を履歴に残し、旧稿を安全に読み比べ、前回の位置から執筆を再開します。履歴の本文、作業位置の記録、通常のファイル保存は、それぞれ別のものです。

原稿自体は C-x C-s で保存します。保存場所や作品設定は Studioと設定、提出用ファイルの生成は 出力を参照してください。

自動履歴と手動記録

Studioでは既定で自動履歴が有効です。原稿を保存したときと、操作が一定時間止まったときに、現在の本文を別の場所へ記録します。idleの既定値は120秒です。まだファイルへ保存していない編集内容も履歴に含みます。

[原稿] → [履歴]、C-c s h、または M-x tategaki-history で履歴一覧を開きます。各項目には日時、文字数、ひとつ前の記録との文字数差を表示します。書き直しを始める前など、区切りを残したいときは [今の原稿を記録] を押します。原稿上のコマンドは M-x tategaki-history-snapshot です。

同じ内容が続くときは項目を増やしません。以前と同じ本文に戻った場合は、内容のSHA-256が一致するスナップショットファイルを再利用します。履歴取得で原稿の本文、Undo、未保存状態は変わりません。

設定の [自動履歴] で自動取得を停止できます。保存間隔を [保存時のみ] にするとidle取得だけを停止します。変数は tategaki-history-enabled と tategaki-history-idle-interval です。Studio外で独立して使う場合は M-x tategaki-history-mode を有効にします。

既定の保存先は ~/.local/share/my-tategaki/history/ です。XDG_DATA_HOME があればその配下を使い、tategaki-history-directory で変更できます。文書ごとの manifest.json と snapshots/<SHA-256>.txt が作られます。現在は古い履歴の自動削除を行いません。ファイル保存や別媒体へのバックアップも併用してください。

旧稿を開く・コピーとして復元する

履歴のボタン結果
[開く]記録した本文を、読み取り専用の別バッファで開きます。
[比較]旧稿と、未保存の変更も含む現在の原稿を比較します。
[コピー復元]旧稿から編集可能な未保存の別バッファを作ります。

復元は現在の原稿を上書きしません。 コピーを確認し、残したい場合は C-x C-w などで別名保存します。元の原稿へ戻す部分を選ぶ場合も、コピーを読んでから作者が編集します。直接実行するコマンドは M-x tategaki-history-restore-as-copy です。

復元コピーの上部の [閉じる] は表示ペインを閉じます。未保存のコピーの本文を自動で破棄する操作ではなく、バッファは残ります。

旧稿と新稿を並べて比べる

履歴の [比較]、または M-x tategaki-diff-buffers で比較します。後者では旧稿と新稿のバッファを選びます。それぞれの内容をコピーした縦書き画面を並べ、変更された行を色分けします。比較のために元の原稿を変更することはありません。

n で次の差分、p で前の差分へ移動します。上部の [閉じる] または q で比較を終了し、元の配置へ戻ります。この比較には外部の diff コマンドが必要です。比較単位は行で、文字ごとの変更追跡や自動マージではありません。

場面の別案を作る

  1. 別案にしたい範囲を原稿で選択します。選択しなければ、現在編集できる範囲をコピーします。
  2. [原稿] → [この場面の別案を作る]、C-c s b、または M-x tategaki-scene-branch を実行します。
  3. 別案の名前を入力し、新しいバッファで書き直します。必要な案にはファイル名を付けて保存します。

別案を作る前に、元の原稿全体を履歴へ記録します。別案は独立した編集用コピーです。元の原稿への自動反映やGitブランチの作成は行いません。比較して採用部分を決めたいときは、上のバッファ比較を使います。

前回の位置と表示を復元する

原稿の保存時、Studio終了時、Emacs終了時に、作業位置と表示状態を記録します。対象にはファイル、カーソル・マーク、ページとスクロール位置、倍率、原稿用紙・見開き・組版、Write/Review、目次の表示状態が含まれます。Reader中に保存しても、執筆に戻ったときの状態を基準に記録します。

次回は開始画面の [前回の原稿を復元]、または M-x tategaki-session-open-last を使います。M-x tategaki-session-restore で最近の原稿を選べます。今の状態を明示的に記録するコマンドは M-x tategaki-session-save です。

セッションファイルは既定で ~/.local/state/my-tategaki/session.json に置きます。XDG_STATE_HOME に対応し、tategaki-session-file で変更できます。ここには本文を保存しません。 保存済みの原稿なら、再度そのファイルを開いて履歴を選び、取得済みの時点までをコピー復元できます。最後の履歴取得後の入力まで復旧できるわけではありません。既に編集中の未保存バッファがある場合はそれを再利用し、ディスクから読み直して置き換えません。

一度も名前を付けて保存していない新規原稿は、セッションの永続的な再開対象になりません。履歴があっても、再起動後に通常の画面から自動で結び直されません。新規原稿はEmacs終了前に名前を付けて本文を保存してください。

Emacs起動時に再開したい場合

自動再開は既定では無効です。必要な場合だけ、初期化ファイルで次のように設定します。

(require 'tategaki-session)
(setq tategaki-session-startup-action 'resume)
;; 開始画面だけを出すなら 'welcome、通常起動に戻すなら nil。

設定画面の保存先にある「このセッションだけ」は、設定値を一時的に使う指定です。このページの、次回へ位置を記録するセッションファイルとは別の機能です。

Readerで通して読む

[原稿] → [Reader]、または M-x tategaki-reader-mode で読書用表示へ切り替えます。本文を読み取り専用にし、診断の印や補助画面を隠して、文庫本風の見開きで表示します。既定の版面は40字×17列です。Readerでは紙面全体が収まる表示を使います。

操作キー
次へSPC / n
前へp / DEL
執筆へ戻るq、または [閉じる・執筆に戻る]

終了時には元の表示設定、診断の表示状態、ウィンドウ配置、読み取り専用だったかどうかを戻します。原稿本文を整形する機能ではありません。画面の版面と、PDF等の出力用書式は別々に設定します。

音読でリズムを確かめる

音読にはmacOSの say コマンドを使います。[音読] または M-x tategaki-tts-play は現在位置から読みます。範囲を指定したい場合は選択して M-x tategaki-tts-read-region を実行します。

操作コマンド
一時停止tategaki-tts-pause
再開tategaki-tts-resume または tategaki-tts-play
停止tategaki-tts-stop。Studioでは C-c s . も使えます。

設定画面の [利用可能なVoice] から実機で使える声を選べます。速度は既定180 words/minuteを基準にした倍率です。読み上げ中の文を本文上で強調しますが、単語単位の正確な音声同期ではありません。原稿を編集すると、古い位置での読み上げを止めます。

固有名詞の読みを指定する場合は、原稿バッファで次のように設定します。置換は音読にだけ使い、本文を書き換えません。

(setq-local tategaki-tts-pronunciations
            '(("小鳥遊" . "たかなし") ("四月一日" . "わたぬき")))

本文はローカルの音読プロセスへ標準入力で渡し、コマンドライン引数やログへ原稿を載せません。say や指定音声が使えない場合は音読の案内を表示します。通常の編集は続けられます。
