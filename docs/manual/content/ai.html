原稿の関連箇所を探し、出典を添えてAIへ相談します。AIは既定では無効です。本文の編集や目次、履歴、ローカル校正は、AIを設定しなくても使えます。

AIの答えは補助資料として表示し、原稿へ自動で書き込みません。まず短い合成文や公開してよい文章で接続を確かめ、その後に自分の作品で使ってください。設定画面の基本は Studioと設定を参照してください。

Ollama・LM Studioへ接続する

  1. 使うAIサーバーを別途起動し、必要なモデルをサーバー側で用意します。Novel Studioはサーバーのインストールやモデルのダウンロードを代行しません。
  2. Studioの [⚙設定] を開き、AIの Provider でOllamaまたはLM Studioを選びます。
  3. Endpoint が、起動したサーバーのURLと一致することを確認します。
  4. [接続テスト] を押します。これはモデル一覧APIへの接続を試し、原稿本文は送信しません。
  5. 次の節の手順でModelとEmbedding Modelを指定し、AIを有効にします。今後も使う設定なら保存先を選び [保存] を押します。
Provider標準Endpoint
Ollamahttp://127.0.0.1:11434/v1
LM Studiohttp://127.0.0.1:1234/v1
llama.cpphttp://127.0.0.1:8080/v1
OpenAI-compatible使用する互換サーバーのAPIルートを入力します。

通信にはOpenAI-compatible APIを使います。Endpointは /v1 までを指定し、/chat/completions は付けません。Providerを変更したとき、Endpointが標準URLなら新しいProviderのURLへ切り替えます。手入力したカスタムURLは保持します。[標準URLを使う] で選択中のProviderの標準値に戻せます。

接続テストの成功は、選んだモデルの文章生成やembeddingが成功する保証ではありません。モデルが未読込、embeddingに非対応、メモリ不足などの場合は、実際の操作で返る案内を確認してください。

ModelとEmbedding Modelを選ぶ

[モデル一覧を取得] を押すと、サーバーが公開しているモデル名を取得します。[一覧からModelを選択] と [一覧からEmbeddingを選択] でそれぞれを選べます。名前を直接入力することもできます。

項目用途
Model質問への回答、作品設定・日時・伏線の候補抽出に使うチャットモデル。
Embedding Model文章を比較用の数値へ変換し、意味索引や関連箇所の検索に使うモデル。

モデル一覧だけでは、そのモデルの用途を判定できません。embeddingに対応するモデルを選んでください。Embedding Modelが空欄の場合はModelの名前を使うため、チャット専用モデルを指定していると索引作成に失敗することがあります。現在はチャットとembeddingに同じEndpointを使います。

一覧取得はAIが無効でも実行でき、本文は送りません。EndpointやProviderを変更すると古い一覧と取得途中の応答を破棄します。0件の場合はサーバー側のモデルとAPIの状態を確認してください。

送信される内容を理解する

操作接続先へ渡すもの
接続テスト・モデル一覧原稿本文を含まないAPIリクエスト。
意味索引を作成・更新対象原稿や登録ファイルを分割した本文。
意味検索検索語のembeddingリクエスト。語句検索へ切り替わった場合はローカルで検索します。
通常のAI相談質問、選択箇所や現在位置の周辺、検索で見つかった本文、採用済み作品設定・作品時間、選ばれた別原稿・資料の一部。
人物・日時・伏線の候補抽出指定した範囲、または順番に分割した現在の原稿全文。

これらの本文送信は、索引作成・相談・抽出などの明示操作から始まります。Novel Studioは localhost / 127.0.0.1 / ::1 のhttp(s)接続をローカルと判定します。それ以外の接続先では、本文送信の前に確認を求めます。tategaki-ai-allow-remote を明示的に t にすると確認なしの外部送信を許可するため、通常は既定の nil のままにします。

この判定は接続先のhostを確認するものです。ローカルサーバーが裏で別のサービスへ転送するかどうかまでは判定しません。完全にローカルで使いたい場合は、サーバー側のモデルと転送設定も確認してください。HTTPリダイレクトには追従しません。

APIキーが必要な場合は、tategaki-ai-api-key-function にキーを返す引数なしの関数を設定します。例えばEmacsの auth-source から取得する関数を利用できます。原稿や作品JSONへキーを記入する必要はありません。

Copilotによる補完は、このAI設定とは独立しています。Copilotの接続先・認証・送信条件はCopilot側の設定に従います。

現在の原稿を検索する

  1. 作品フォルダへ原稿を保存し、AI設定を確認します。
  2. [AI] でAssistantを開き、[意味索引を作成] を押します。原稿上では M-x tategaki-semantic-index でも実行できます。
  3. [検索]、C-c s /、または M-x tategaki-semantic-search で探したい内容を入力します。
  4. 結果の章・位置をクリックして、原稿を読みます。

索引は現在の原稿を段落や章・場面の区切りで分け、長い段落は既定800字を目安に分割します。採用済みの人物名・別名の出現、登録Sceneの登場人物・視点、採用済みの時系列も手掛かりにします。名前が出たことと、その人物が内容を知っていることは区別します。

索引は作品の .tategaki/index/ に保存します。原稿内容、Endpoint、Embedding Modelが一致するときだけ再利用します。本文を変更した後は索引を作り直してください。

索引が未作成・古い、AIが無効、またはembedding通信が失敗した場合は、語句の一致による lexical検索 へ切り替えます。結果に示される検索方式を確認してください。AIを設定しなくても、この語句検索は使えます。

原稿について相談する

[AI]、C-c s a、または M-x tategaki-assistant で、画面下側に相談ペインを開きます。> の後に質問を書き、RET または C-c C-c で送信します。例えば「主人公が鍵を見つけた場面を確認したい」のように、確かめたい対象を具体的に書きます。

プリセットから相談内容を選ぶこともできます。選択した文章については M-x tategaki-ask-region、指定人物については M-x tategaki-ask-character を使います。人物相談には後述の知識範囲の制限がかかります。

回答は「原稿から確認できること」「推測」「不明」「参照箇所」を分けるようモデルへ指示しています。ただし、モデルが正しく読み取ることや、必ずこの形式に従うことは保証しません。結論だけでなく参照箇所を開いて確認してください。

出典から本文を確かめる

[第3章:1234] のようなラベルが回答に出た場合、実際にモデルへ渡した出典に一致するものだけがリンクになります。数字は行番号ではなくEmacsの原稿位置です。別原稿は [原稿:ファイル名:章:位置]、資料は [資料:ファイル名:位置] と区別し、同名の出典が重なれば #2 などを付けます。

回答待ちに原稿や参照ファイル、コレクションの対象が変わった場合は、古い文脈や出典をそのまま使いません。引用を開くときにも内容を照合し、変わっていれば再検索を求めます。古い回答の位置が現在の本文を正しく指すと推測しないための仕組みです。

取消・閉じる・再開

[取消] または C-c C-k で処理中の相談を取り消します。上部の [閉じる]、q、C-c C-q は、処理を中止してAssistantのペインを閉じ、原稿へ戻ります。設定など他のペインは残します。

会話と入力途中の質問はAssistantのバッファに残り、再度開くと続けられます。閉じた後に遅れて届いた回答でペインを再表示することはありません。この保持は開いているEmacs内のもので、会話を永続的に保存する機能ではありません。

別原稿と資料をコレクションへ登録する

[原稿] メニューの原稿・資料コレクション、C-c s c、または M-x tategaki-corpus で管理画面を開きます。現在の原稿だけの索引とは別に、作者が選んだファイルを横断検索できます。

  1. [原稿を登録] / [資料を登録] でローカルファイルを1つずつ選びます。登録はパスを記録するだけで、この段階では本文の読込・AI送信を行いません。
  2. [対象] / [除外] で検索に使うものを決めます。
  3. [意味索引を更新] を押すと、対象ファイルの本文をembeddingサーバーへ送ります。
  4. [検索] または M-x tategaki-corpus-search で検索し、結果から出典へ移動します。処理中は [中止] で止められます。

通常のAssistant相談にも、有効なコレクションの検索結果を文脈上限まで組み込みます。ファイルがEmacsで編集中なら未保存のバッファ本文を優先し、ディスクの内容で置き換えません。内容・対象一覧・接続先・モデルが途中で変わると古い結果を破棄します。索引が使えないときは語句検索へ切り替えます。

登録は .tategaki/corpus.json、索引は .tategaki/corpus-index.json に保存します。除外や登録解除は元ファイルを削除しません。フォルダ全体の自動登録や再帰走査は行いません。ファイルはテキストとして読み、PDF・Word・画像の変換やOCRは提供しません。既定の1ファイル上限は5MiBです。

作品フォルダに直接置く資料

作品の .tategaki/resources/ 直下にある .txt / .md / .org は、通常の相談時に語句検索の対象になります。サブフォルダを再帰的には読みません。シンボリックリンクは除外し、最大100ファイル、既定では1ファイル2MB・一度に合計4MBまで読みます。

この方法で置いた資料も、文脈として選ばれればAIへ送信されます。コレクションに登録して [除外] にしたファイルは、この資料フォルダ内にあっても通常相談から除外します。

人物と「この時点」の知識を制限する

人物相談は現在の原稿位置を上限とし、さらに、その人物が知っていると作者が登録した範囲だけを参照します。本文として許可されるのは、その人物を known-by に含む採用済みFactの出典、または採用済みSceneの visibility で許可した引用範囲です。

Sceneの視点人物や登場人物に名前があるだけでは、その場の情報を知ったとは扱いません。未注釈の周辺本文、章名、資料、別原稿、一般の時系列を人物の知識へ混ぜず、許可した情報がなければ不明として回答するよう指示します。「この時点」など位置を制限する一般質問も、資料・別原稿の検索を行いません。

これは原稿上の位置と、作者が採用した注釈による制限です。回想・予告・嘘・伝聞を完全に理解したり、人物が何を認識したかを自動で確定したりする機能ではありません。注釈の付け方と読者との差の確認は 人物・作品設定の知識比較を参照してください。

接続エラーや古い索引の対処は トラブルシューティング、コマンドを探す場合は リファレンスを使ってください。
