CHAPTER 11

困ったとき

表示・入力・出力の切り分けと、現在の対応範囲。

症状に近い項目から確認してください。本文の表示、設定の保存、AI接続、ファイル出力は別の処理です。まず短い原稿で再現するかを確かめると、問題の場所を絞れます。

最初に確認すること

  1. 本文の描画がおかしい場合は C-c C-l で再描画します。従来プレビューでは g を使います。
  2. C-c C-c で縦書きを終了し、元の文字・改行・注記を確認します。表示の切り替えは本文やUndoを変更しません。
  3. *Messages* のエラー全文を確認します。AIや出力は、それぞれのペイン・ジョブログにも結果を表示します。
  4. M-x emacs-version と M-: (locate-library "tategaki") で、Emacsの版と読み込み先を確認します。

次を M-: で評価すると、描画・入力連携に必要な機能の有無を読めます。設定や本文は変更しません。

(list :emacs emacs-version
      :window-system window-system
      :graphical (display-graphic-p)
      :svg (image-type-available-p 'svg)
      :ns-working (fboundp 'ns-insert-working-text)
      :ns-marked (fboundp 'ns-insert-marked-text)
      :ime-offset-x (boundp 'mac-ime-panel-offset-x)
      :ime-offset-y (boundp 'mac-ime-panel-offset-y))

Studio・縦書きを開始できない

症状確認・操作
コマンドが見つからないリポジトリを load-path に追加し、(require 'tategaki) を評価します。導入手順を確認してください。
Studioが開始画面を表示する「新しい小説を書く」または「原稿を開く」を選びます。既存のtext-mode系バッファではその原稿を使用します。
text-modeが必要と言われる新規のfundamental-modeバッファなら M-x text-mode を実行してから開始します。
本文を入力できないReader・履歴表示・比較用コピーなど、読むための画面ではないか確認します。Readerは上部の「閉じる・執筆に戻る」か q で終了。元原稿が読み取り専用の場合はその制限を引き継ぎます。
更新した機能が出ない古いインストール先や.elcを使っていないか確認します。実行中のEmacsには読み込み済み定義が残るため、本文を保存してから新しいコードで再起動してください。Dockerイメージの更新は別途必要です。

本文が小さい・用紙寸法が反映されない

まず設定の文字サイズで「リセット」、または M-0 を実行し、負の倍率になっていないか確認します。その後「＋」または M-+ で拡大します。

「用紙全体を画面に収める」が有効だと、20×20の見開きなどを画面幅へ縮小します。文字を優先して読みたい場合はこの設定を無効にしてください。既定では無効で、幅に入る列だけ表示し、残りは下の横スクロールバーで移動します。論理ページの字数・列数は維持されます。

固定用紙の縦字数は高さへ収めるため、拡大には上限があります。さらに大きくする場合は原稿用紙を「フリー（文字サイズ優先）」にします。自由寸法は「縦字数」「列数」へ各1〜200の整数を入力し、「寸法を適用」→保存先を選ぶ→「保存」の順で操作します。入力しただけでは表示へ反映されません。

Readerは用紙全体を収める表示を一時的に使います。閉じると執筆時の設定に戻ります。画面の用紙設定はPDF・DOCXの出力設定へ自動転記されません。

保存した設定が戻る・別作品にも反映される

設定の優先順位はセッション → 作品 → 全作品の既定値 → Lispの値です。上位にある値は下位へ保存しただけでは解除されません。例えばセッションの文字サイズがあれば、全作品の既定値へ別の値を保存しても現在稿の表示にはセッション値が残ります。

「このセッションだけ」は現在のバッファ内の設定で、バッファを閉じると終了します。「この作品」は最寄りの .tategaki/project.json、「全作品の既定値」は tategaki-project-default-file へ保存します。新しい原稿は専用フォルダーへ保存してから作品設定を保存すると、作品間の意図しない共有を避けられます。

保存は、その画面で編集・適用した項目だけが対象です。同じ値を別の保存先へ置きたい場合も、値を選び直すか「寸法を適用」してから保存します。「元に戻す」は画面を開いた時点へ戻す操作で、保存後に押した場合は新しい未保存変更になります。壊れたJSONは自動で上書きせずエラーを表示します。

ルビ・縦中横が記法のまま見える

M-x tategaki-typeset-edit で組版付き編集を開始します。tategaki-typesetting が nil の場合は文字単位表示です。組版にはGUI・SVG対応・tategaki-glyph-use-svg = t が必要で、利用できない場合は原文表示へ戻ります。

組版が有効でも tategaki-typeset-annotation-display = raw なら注記の記法を見せます。C-c C-a で表示を切り替えてください。未完成・未対応の注記は原文のまま残ります。対応記法は組版と注記にあります。

文字が四角になる・約物の向きがおかしい

設定のフォント欄で、インストール済みの日本語書体を選びます。本文のfaceは tategaki-face、従来プレビューは org-tategaki-preview-face です。M-x customize-face からも変更できます。

「、」「。」だけが欠ける場合は、表示用の約物置換を一時的に無効にして比較できます。本文の文字コードを書き換える設定ではありません。

(setq-local tategaki-layout-use-vertical-forms nil)
(tategaki-refresh)

結合文字、異体字、ZWJ絵文字の字形はフォントとEmacsの描画環境にも依存します。出力用コンテナのフォントとは別です。従来プレビューでは org-tategaki-preview-use-vertical-forms を調べ、g で更新します。

IMEの変換・候補位置がおかしい

まず変換を確定または取消し、C-c C-l で再描画します。確定前の文字が原稿ファイルや文字数へ加わることはありません。確定後は通常の本文編集としてUndoできます。

縦書きの未確定表示は、対応するNS入力関数があるmacOS版Emacsで利用できます。OSの候補一覧自体は横書きです。候補位置の補正には mac-ime-panel-offset-x / mac-ime-panel-offset-y が存在して整数値であることも必要です。同名の変数を作るだけで、未対応のEmacsへ機能が追加されるわけではありません。

Corfu・Copilotの候補はIMEと別の補助表示です。候補操作中はそのキー割り当てを優先します。問題を報告する場合はEmacsの配布元、上のNS診断値、変換のどの段階で起きたかを添えてください。

移動キー・ページ送りが想定と違う

症状確認・操作
C-fなどが見た目の方向へ動かない既定は通常のEmacsの移動です。画面方向を使う場合は tategaki-physical-navigation を t にします。矢印キーは縦書きの方向へ動きます。
C-vが論理的な次ページへ行かないC-v/M-vは画面単位です。固定版面のページ番号を指定する場合は tategaki-goto-page（C-c C-p）。
本文ではなく補完候補が動くCorfu候補操作中は候補の移動・ページ送りを優先します。候補を採用・取消してから本文を移動します。
他パッケージのコマンドが実行されるC-h k の後にキーを押し、実際の割り当てを確認します。Studioと目次、Readerでは使えるキーが違います。

下部スクロールバーは右端が先頭、左端が末尾です。キー一覧はリファレンスを参照してください。

目次が出ない・章が更新されない

Studio上部の「目次」または C-c s o で開閉します。本文のカーソルを残したまま開け、Writeに戻っても表示中の目次は維持します。C-c C-o は目次へフォーカスを移す従来の操作です。

第一章、# 第一章、* 第一章 などを使えます。空白なしの #第一章 / ##第一節 も認識しますが、任意のタイトルは # プロローグ のように空白を入れます。入力中の更新はidleまでまとめます。すぐ確認する場合は目次内で g を押します。

narrowing中はその範囲だけを一覧にします。タイトルクリック・RETは本文へ移動し、三角クリック・TABは一覧だけを折りたたみます。本文の章集計や出力の電子目次は別の見出し設定を使います。

括弧が二重になる・字下げが変わる

Smartparensなど別の括弧補完を使う場合は、tategaki-writing-electric-pair を nil にして執筆支援を再開します。M-x tategaki-writing-mode で切り替えられます。

自動字下げは改行・段落先頭の入力に作用し、既存原稿を開いた時や貼り付けた時に一括整形するものではありません。脚本モードのTAB・整形コマンドは本文の空白を変更します。小説／脚本の規則は執筆支援で確認してください。

LM Studioを選んだのにOllamaと表示される

設定のProvider欄にある現在値のボタン、例えば [Ollama ▼] をクリックしてLM Studioを選び、保存先を選んで「保存」します。文字列の横のラベルだけでなく現在値のボタンから選択できます。

旧設定にはEndpointだけがあり、Provider項目がない場合がありました。現行版は未指定のProviderだけを標準の localhost / 127.0.0.1 のポート1234・11434・8080から補完します。独自URLでは推定せず、明示ProviderやLispのローカル値も上書きしません。

選択後も戻る場合は保存先の優先順位を確認します。EndpointとモデルがLM Studio向けでも、上位のセッション設定にOllamaが残っていればそちらが優先します。Providerを選ぶと標準URLは切り替わりますが、独自URLは保持します。「標準URLを使う」で選択中Providerの標準値へ戻せます。

モデル一覧・接続・相談が失敗する

症状確認・操作
接続できないサーバーを起動し、待受URLを確認。Endpointは /v1 まで指定します。LM Studioの標準例は http://127.0.0.1:1234/v1、Ollamaは http://127.0.0.1:11434/v1。
モデル一覧が0件サーバー側のモデルを確認し、再取得します。一覧取得は本文を送らず、AI無効でも実行できます。
接続成功なのに相談できない接続テストはモデル一覧APIです。AIの有効化、実際の会話用モデルID、モデルの稼働状況を確認します。
接続先変更で一覧が消える古い接続先のモデルを選ばないための動作です。新しい接続先で再取得します。
回答待ちが続くサーバー側の処理とメモリ状況を確認。既定のHTTPタイムアウトは120秒です。Assistantの取消・閉じるで中止できます。
回答・引用が古いと言われる依頼中に原稿や資料が変わった場合は古い結果の使用を止めます。現在の原稿で再実行してください。

AIは本文を自動修正しません。非localhostのEndpointへの本文送信には確認があります。ローカルサーバーがさらに外部へ転送するかはサーバー側の設定も確認してください。詳しくはAI接続と相談。

意味検索が語句検索になる・embeddingエラーが出る

会話用ModelとEmbedding Modelは別の用途です。一覧に名前があるだけではembedding対応を判別できません。Embeddingを空欄にすると会話用Modelを使いますが、多くの会話用モデルはembedding APIに対応しません。対応モデルを別途選んでください。両方で同じEndpointを使います。

意味索引は明示的に作成します。未作成、原稿の変更、Endpoint・Embedding Modelの変更、embedding通信失敗では語句検索へ切り替わります。原稿を整えた後で M-x tategaki-semantic-index を実行してください。別原稿・資料は「作品・資料」で登録・検索対象の指定・索引作成が必要です。フォルダー全体の自動走査やPDF・Word・OCR取り込みは行いません。

人物としての相談で「不明」になる場合は、採用済みの知識や許可された本文範囲があるか確認します。単に登場した、POVに指定された、名前が書かれたという理由だけで、その人物へ全情報を渡すことはありません。人物と知識の登録を参照してください。

履歴や執筆位置が見つからない

履歴の既定保存先は ~/.local/share/my-tategaki/history/、セッションの記録は ~/.local/state/my-tategaki/session.json です。XDG_DATA_HOME / XDG_STATE_HOME や対応する設定変数で変わります。C-h v で tategaki-history-directory と tategaki-session-file の現在値を確認できます。

履歴は保存時と既定120秒のidle時に作り、同じ本文の内容を重複保存しません。履歴を無効にしている、idle間隔がnilで保存していない、といった場合は新しい記録が増えません。必要な時点は tategaki-history-snapshot で記録できます。

セッションは本文のバックアップではありません。復元できるのは取得済みの履歴までです。ファイル名のある原稿を再度開き、履歴の「コピー復元」で別バッファへ取り出します。一度もファイル名を付けていない新規原稿はセッションの再開対象外で、再起動後の通常の履歴UIにも自動で結び付きません。終了前に名前を付けて本文を保存してください。元原稿を自動で上書きする操作はありません。

ペインを閉じたい・閉じても処理が続く

補助ペイン上部の「閉じる」はスクロールしても残ります。Lookupの見出し・本文・辞書一覧にもあります。多くの読む画面は q でも閉じられます。編集可能なコピーでは文字入力を妨げないよう、上部の閉じるを使います。

  • 設定：未保存変更は保存・破棄・戻るを選びます。
  • Assistant・検索：その要求を取消し、後から届いた応答でペインを開き直しません。
  • 出力の状態・ログ：閉じても出力は続きます。停止は tategaki-export-cancel。
  • 履歴の復元コピー・別案：閉じても未保存のコピーはバッファに残ります。
  • 比較・Reader：専用の閉じるで元の配置・表示へ戻ります。

Studioの終了と縦書きの終了も別です。Studioは tategaki-studio-mode、縦書き自体は C-c C-c で終了します。

原文・文字数・出力の内容が違って見える

↵、⇥、□ は改行・タブ・末尾の表示記号です。保存本文へ追加しません。ルビや傍点も表示では組版しますが、原文には注記が残ります。本文だけのテキストが必要なら出力の txt/body.txt、注記付き原文は txt/source.txt を使います。

400字詰換算は文字数からの計算で、改行・空きマス・組版を含む実ページ数とは異なります。編集画面、PDF、DOCX、リフローEPUBのページ数も一致するとは限りません。出力の既定範囲は全文です。部分出力は C-u M-x tategaki-export で明示します。

Docker出力が始まらない・失敗する

# リポジトリのフォルダーで実行
./bin/tategaki-export build
./bin/tategaki-export doctor

Docker Desktopを起動してから確認します。Emacsだけでdockerが見つからない場合は、Emacsの exec-path とPATHを確認してください。ソース更新後はイメージの再構築も必要です。

ジョブができていれば M-x tategaki-export-status からレポートとログを開きます。未対応注記、要求フォント不足、外部コマンドの時間上限などは形式別に報告されます。一形式の失敗でほかの完成物まで失敗とは限りません。途中ファイルは .work/ に残り、再実行は新しいジョブになります。

CLI入力はUTF-8です。CP932などへの本文TXT出力では、表せない文字を黙って置換せずエラーにします。設定・取消・完成物の場所は出力手順を参照してください。

出力形式の制限

形式主な制限
DOCXLibreOfficeで描画・再保存を確認。Wordの実表示は未確認。一部ZWJ絵文字の表示差あり。固定グリッドは試験的設定。
PDF本文照合はNoto Serif CJK JP限定。固定字数・列数、PDF/X、印刷所別の塗り足し・色変換は未対応。
EPUBApple Booksで通常章の目次・本文移動を確認。記号を含む特定の章名では目次のXMLエラーが残る。Kindle Previewerは未検証。画像表紙・フォント埋め込みは未対応。

具体的なBooksの条件などは出力後の確認を参照してください。EPUBCheck成功だけで全閲覧アプリの互換性を判断しないでください。

確認環境

主な操作確認は2026年9月のmacOS・GUI版GNU Emacs 31.1（Emacs-takaxp）・SVG対応環境です。パッケージの対象はEmacs 27.1以降ですが、全OS・全ビルドを実機確認したわけではありません。NSのIME APIがない環境では連携範囲が異なります。

AIは合成原稿を使ったLM Studioの実モデルで相談・embedding・候補抽出を確認しました。Ollamaの切替はfixtureによる検証を含み、同じ条件で全Providerの実モデルを確認したわけではありません。DockerはApple Silicon / linux aarch64、DOCXはmacOS LibreOffice、EPUBはApple Booksで確認しています。amd64、Word、Kindle Previewerは未検証です。

試験の実施日・条件・結果はStudio、編集・組版、出力の検証記録へ残しています。これらは過去の検証記録であり、現在の設定手順はこのマニュアルを参照してください。

問題を報告する

再現する短い原稿、操作手順、エラー全文、OSとEmacsの版、読み込み先、関連設定を添えてください。目次なら見出しの記法、IMEなら変換の段階、AIならProvider・Endpoint・モデルと失敗した処理、出力なら形式・プロファイル・レポートが役立ちます。認証キーや非公開原稿全体を載せる必要はありません。
