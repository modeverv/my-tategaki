# 縦書き組版・執筆支援の実装・検証記録

検証日: 2026-09-26〜27。作業前の状態は `887036a` にコミットし、
`codex/vertical-typesetting` ブランチで開発した。コミット者は Codex。

## 使い始める

`M-x tategaki-typeset-edit` で現在のテキストバッファを組版表示にする。
通常の `tategaki-edit` は従来の原文表示を保つ。

```elisp
(setq tategaki-typesetting t
      tategaki-typeset-latin-orientation 'rotate)

;; 必要な文書で固定版面・見開き・罫線を選ぶ。
(setq-local tategaki-manuscript-size '(20 . 20)
            tategaki-manuscript-spread t
            tategaki-manuscript-grid t)
```

ルビは選択範囲に `C-c C-r`、注記の原文表示への切り替えは `C-c C-a`、
ページ指定は `C-c C-p`。設定・対応注記・その他のコマンドは [README](../README.md) を参照。

## 実装範囲

| 項目 | 対応 |
| --- | --- |
| 検索・校正 | text/overlay face の反映、isearch・lazy highlight・query replace・Flymake、色・反転・縦方向の下線 |
| 長文 | 段落と列の索引、局所解析、可視セルのみの画像化、フォント・描画・文字数のキャッシュ |
| 見た目の一文字 | 結合濁点、異体字セレクタ、修飾絵文字、ZWJ、国旗の組、原文位置との対応 |
| 禁則・列末 | 設定可能な行頭・行末禁則、ぶら下げ、任意の追込、リーダー／ダッシュ対の分割禁止 |
| 縦中横・欧文 | 明示注記、自動2桁数字・2文字の感嘆符／疑問符、単語の90度回転、長語の分割 |
| ルビ・強調 | 対応する青空記法、読みの編集、親文字の右のルビ、傍点・傍線、原文表示切り替え |
| 原稿・ページ | 20×20／40×30、縮小して固定字詰めを維持、罫線、見開き、現在／総ページ、ページ指定 |
| 統計 | 全文・選択・章、空白／改行／注記の集計規則、400字換算と本文配置枚数、目標残り |
| 横スクロール | 下部の表示専用バー、右から左への列スクロール、クリック・ドラッグ、ページ指定との切り替え |
| 執筆支援 | 全角一字下げ・会話文の調整、見出しの除外、バッファ限定のElectric Pair、設定復元 |
| 脚本 | 人物名・台詞・ト書きの挿入と字下げ整形。全角空白を含む通常テキストとして保存・Undo |
| アウトライン | 見出し一覧、階層の開閉、本文位置への移動、現在章の追従、編集後の更新 |

![実装後の組版表示。ルビ、縦中横、回転欧文、絵文字、傍点・傍線を原稿用紙へ配置。](images/tategaki-typesetting.png)

本文・元の位置・保存・UndoはEmacsのバッファに置いたまま、表示だけを組み替える。
IMEと補完は独立した境界を持つ仮入力として配置し、確定・採用は元の入力処理に任せる。

## 自動・GUI検証

### 全角字形の横位置補正（2026-09-28）

macOSのSVG表示で `text-anchor="middle"` を使うと、字面の幅と左側の余白に応じて
「日」「本」「人」「・」「ー」などの横位置がずれることを実画面で確認した。
全角の漢字・仮名・縦書き記号は、全角枠の左端を明示して同じ列の中心に揃える。
句読点の右上配置や小書き仮名の字形内位置は保持し、ルビにも同じ補正を適用する。
結合濁点・異体字セレクタを含む文字にも対応し、欧文・縦中横・半角仮名・絵文字の
中央揃えは従来どおり。フォント設定の変更は不要。

- 全バッチ315件中311件成功・失敗0・GUI専用4件スキップ。
- 描画部品GUI3件、組版GUI9件成功。
- 使用中のNS Emacs 31.1へ反映し、報告された原稿の同じページで位置の改善を確認。
  原稿本文とカーソル位置、変更済みフラグを保持した。

### 専用台本モード追加後（2026-09-27 01:40）

役割別の色、シーンの挿入・移動・一覧、人物名の補完、人物名行末のRETから台詞入力、
TAB整形、範囲／全文の字下げを用意した。本文を読み込んだだけでは整形せず、横書きでも利用できる。

- 台本用バッチ22件成功。開始／終了時の本文・point・narrowing・Undo・modified状態保持、キー優先順位、
  人物名候補の編集追従とバッファ分離、シーン一覧とImenu、字下げ・Undoを検証。
- 専用NS GUI4件成功。実際のキーボードマクロによるRET・台詞入力・Undo、source faceからSVGへの反映、
  遠いシーンへの移動と実カーソル、縦書き終了後の横書き脚本入力を検証。
- 全バッチは313件中309件成功・失敗0・GUI専用4件スキップ。
- 従来の執筆支援GUI2件も再実行して成功。下記51件すべての再実行ではない。
- `tategaki-script.el`、接続する`tategaki.el`、新しいテスト2ファイルの厳格バイトコンパイルは警告なし。

### 組版・スクロール・執筆支援の検証（01:00時点）

検証環境は Apple Silicon macOS 27.0 / NS Emacs 31.1。
GUI試験はすべて専用プロセス・使い捨てバッファで実行する。
ユーザーの原稿へ試験文字を入力していない。

実行中のユーザーEmacsにも読み込み済みで、ファイルバッファの変更tick・point・Undo・modified状態の保持を確認した。

ぶら下げ句読点は、半セルの占有高とフォントの高さを分離した。
通常時と同じ本文サイズで描き、列末で縮小しない。句読点各種と文字間隔0/20pxをGUIで確認した。
描画用SVGをPNGへ変換した確認でも、通常セルと半セルで句読点のインク寸法が一致し、欠けがなかった。

従来の入力・IME・余白の3つのGUI試験では、新しい自動字下げを明示的に無効化して
原文入力の基準を維持した。執筆支援を有効にした経路は専用GUI試験で検証した。
バーのドラッグ試験は実表示から得たマウス位置に対してイベントを供給するもので、OSのマウス操作そのものを自動化していない。
開いていた `a.txt` へ更新を読み込み、本文tick・point・Undoオブジェクト・modified状態の保持とバーの生成を確認した。

NS試験はインストール済みの実 `ns-put-marked-text` 等を呼び出す。
OSのキー操作から変換候補を選ぶまでの一連の操作を自動化した試験ではない。
Copilotは実表示・採用関数を使い、ネットワークへの生成要求を行わない。
Corfuは実子フレームの位置を検証し、右端に収める標準の補正も許容する。

## 描画まで含む性能

再現: 専用GUIで `test/tategaki-performance.el` を起動する。
100列×40行のフレーム、1縦列30字、組版表示、標準の間隔・フォント・統計表示。
各100文字に異なる漢字を1字含む生成本文を使い、改行なし／99字ごと改行の2種類を測った。
各操作は20回。入力は本文中央へ1字追加して再描画、移動は1文字移動、ページは往復移動。
すべて `redisplay` 完了までを含む。OSのキーイベント配信時間は含まない。

| 字数 | 本文形状 | 初回表示 ms | 入力 p95 ms | 1字移動 p95 ms | ページ移動 p95 ms |
| ---: | --- | ---: | ---: | ---: | ---: |
| 1,000 | 単一段落 | 729.0 | 48.1 | 45.6 | 70.8 |
| 1,000 | 短い段落 | 137.0 | 31.7 | 32.8 | 56.9 |
| 10,000 | 単一段落 | 87.7 | 51.8 | 47.1 | 69.6 |
| 10,000 | 短い段落 | 69.8 | 46.2 | 35.0 | 60.6 |
| 100,000 | 単一段落 | 107.0 | 71.8 | 34.3 | 54.1 |
| 100,000 | 短い段落 | 181.0 | 58.3 | 37.6 | 61.7 |
| 200,000 | 単一段落 | 144.6 | 91.8 | 34.1 | 57.9 |
| 200,000 | 短い段落 | 456.5 | 86.8 | 39.6 | 63.5 |

初回表示は各1回で、最初の1,000字だけがプロセス内の最初の表示になる。
後続ケースはライブラリや画像キャッシュが温まっているため、独立したコールド起動の比較ではない。
生の値・GC回数は [測定データ](vertical-typesetting-timings.sexp) に保存した。

この生成本文では10万字の入力p95 100ms目標を満たした。
複雑な注記・絵文字・異なるfaceが大量にある本文、外部パッケージの重いフック、
実際のIME候補処理を含む全環境で100ms以内を保証するものではない。

各描画中だけ `tategaki-render-gc-threshold`（既定16MiB）を下限としてGCの割当閾値を一時的に上げ、
短時間にGCを何度も繰り返すことを防ぐ。正常終了・エラーのどちらでも元の設定へ戻る。
これはメモリ使用量の上限ではない。OS・画像キャッシュを含む最大メモリ量の系統的な比較は未実施。

## 制約

- 組版の描画にはGUIとSVGが必要。利用できない場合は設定値を保持して従来の原文表示へ戻る。
- 青空形式はREADMEに記載した注記に限定。ルビの読みは親文字へ均等配分し、長い読みは縮小する。
- JLReq・UAX #29・全青空注記の完全実装ではない。フォントの全OpenType縦書き字形も対象外。
- 一部だけを検索・選択した結合文字や縦中横は、表示セル全体を強調する。原文の範囲は変更しない。
- 細かい原文編集には注記の原文表示またはEmacs本来の論理文字移動を使える。
- PDF／印刷／EPUBは未実装。アウトラインの階層開閉は一覧内だけで、本文の折りたたみや章の並べ替え専用UIは含まない。
- 脚本はREADMEの簡易形式。印刷時の役名欄・提出先固有の書式・専用出力は未実装。
- 上記性能表はG01〜G12実装時の測定。横スクロール・執筆支援・アウトラインの追加後は同じ性能測定を再実施していない。
