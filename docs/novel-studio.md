# Novel Studio の使い方

Novel Studio は、通常の原稿バッファを中心に、設定・履歴・辞書・校正・作品資料・AI相談・音読を開くための執筆画面です。表示設定や検査結果を本文へ埋め込まず、保存・Undo・選択範囲・検索はEmacsの原稿に対して働きます。

本文の正本は常に元の原稿バッファです。索引、AI回答、世界設定、診断、比較用コピーは補助情報であり、原稿へ自動反映しません。AIや任意の外部ツールが利用できなくても基本編集を続けられます。

## 最初の原稿を書く

リポジトリを `load-path` に追加して、通常どおり読み込みます。Studio用の追加パッケージやPython環境は不要です。

```elisp
(add-to-list 'load-path (expand-file-name "~/src/my-tategaki"))
(require 'tategaki)
```

1. `M-x tategaki-studio` を実行します。原稿を開いていない場合は開始画面が出ます。
2. `[新しい小説を書く]` または `[原稿を開く]` をクリックします。既に `text-mode` の原稿を開いていれば、その原稿でStudioが始まります。
3. 上部の `[⚙設定]` でタイトル・著者名を入力します。フォント・文字サイズ・原稿用紙・余白は、その場で原稿に反映されます。
4. 設定の保存先を選び `[保存]`、`[閉じる]` を押します。本文は `[原稿]` → `[保存]`、または `C-x C-s` で別途保存します。新しい作品は専用フォルダを作って原稿を保存すると、設定資料もまとめやすくなります。
5. 執筆中はWrite、推敲中は `[Review]` を使います。`[原稿]` から各機能をクリックで開けます。

`M-x tategaki-studio-mode` または `[Studio を終了]` でStudioの履歴・検査・専用UIを終了し、軽量な縦書き編集へ戻せます。縦書き自体の終了は従来どおり `C-c C-c` です。

## Write / Review と操作

Writeは原稿と、表示中の目次を残して推敲用の補助ウィンドウを閉じます。Reviewは前の推敲レイアウトを戻し、初回はアウトラインを開きます。辞書・設定資料・検査結果は右側、Assistantは下側に表示します。

| 操作 | `M-x` コマンド | Studio内のキー |
|---|---|---|
| Write / Review | `tategaki-studio-write` / `tategaki-studio-review` | `C-c s w` / `C-c s r` |
| 目次の表示 / 非表示 | `tategaki-studio-toggle-outline` | `C-c s o` |
| すべての操作を表示 | `tategaki-studio-menu` | `C-c s m` |
| 設定 | `tategaki-settings` | `C-c s s` |
| 履歴 | `tategaki-history` | `C-c s h` |
| 辞書 | `tategaki-lookup-word` | `C-c s d` |
| 校正一覧 | `tategaki-diagnostics-list` | `C-c s p` |
| AI相談 | `tategaki-assistant` | `C-c s a` |
| 関連箇所を検索 | `tategaki-semantic-search` | `C-c s /` |
| 登録原稿・資料の横断検索 | `tategaki-corpus` | `C-c s c` |
| 読者と人物の知識差 | `tategaki-knowledge-compare` | `C-c s k` |
| 時系列 / 伏線 / 人物の話し方 | `tategaki-timeline` / `tategaki-foreshadow` / `tategaki-voice` | `C-c s t` / `C-c s f` / `C-c s v` |
| 場面の別案 | `tategaki-scene-branch` | `C-c s b` |
| 音読を停止 | `tategaki-tts-stop` | `C-c s .` |

ボタン類は `TAB` / `S-TAB` で移動し、`RET` でも実行できます。原稿の従来の移動・選択・拡大縮小キーも使用できます。

各補助ペインの上部には、スクロールしても残る `[閉じる]` があります。原稿メニュー、設定、目次、校正、履歴、比較、人物・設定、検索結果、Lookupの見出し・本文・辞書一覧・ヘルプ、出力状態・ログからマウスで原稿へ戻れます。他のペインは残します。比較画面は比較を終了して元の配置へ戻り、設定に未保存変更がある場合は保存・破棄を選びます。復元コピーや別案を閉じても未保存の本文はバッファに残り、出力ログを閉じても出力処理は続きます。

## 執筆中の目次・アウトライン

上部の `[目次]` を押すと、右側に章・節の一覧が開きます。本文にカーソルを残したまま表示でき、Write中も開いておけます。見出し名のクリックでその位置へ移動し、三角をクリックすると配下の節を折りたたみます。現在いる章は強調され、本文で見出しを追加・変更すると少し待って一覧へ反映されます。

既定では `第一章`、`第2節` のような章・節番号、Markdownの `# 第一章` / `## 第一節`、Orgの `* 第一章` / `** 第一節` を認識します。日本語の番号付き見出しは、空白を省いた `#第一章` / `##第一節` でも使えます。任意のタイトルは `# プロローグ` のように空白を入れます。

もう一度 `[目次]` を押すか、目次上部の `[閉じる]` で閉じられます。キーボードでは `C-c s o` で表示を切り替え、目次内の `RET` で移動、`TAB` で折りたたみ、`q` で閉じます。表示状態はセッション復元やReaderとの往復でも保持します。

## 設定と保存先

設定画面の上部にタイトル・著者名・言語・識別子があります。その下で表示、執筆支援、自動履歴、校正、AIのモデル/接続先、音読のVoice/速度を変更できます。Lispで設定した独自の原稿用紙寸法や履歴間隔も、現在の値として選択肢に残ります。

文字サイズの `[＋]` / `[−]`、または `M-+` / `M--` で本文を拡大・縮小します。固定原稿用紙や見開きでも、既定では文字サイズを優先して入る列数だけ表示し、残りは下部の横スクロールで読めます。20×20などの論理的な用紙寸法とページ数は維持します。縦の字数は画面高に合わせるため、縦いっぱいになると拡大は上限に達します。さらに大きく読む場合は原稿用紙を「フリー（文字サイズ優先）」にします。

原稿用紙はプリセットに加え、`縦字数` と `列数` へそれぞれ1〜200の整数を入力し、`[寸法を適用]` で自由な寸法にできます。入力途中は原稿を変更せず、2つの値が正しいときにまとめてプレビューします。適用後、保存先を選んで `[保存]` を押します。`フリー（文字サイズ優先）` は固定の字数・列数を使わず、フォントとウィンドウの大きさから表示する字数・列数を決めます。

`[用紙全体を画面に収める]` を有効にすると、従来どおり全ページ・見開きを画面幅へ縮小します。Readerはこの全体表示を一時的に使い、執筆へ戻ると元の設定に戻します。

| 保存先 | 有効範囲 | 保存場所 |
|---|---|---|
| このセッションだけ | 現在の原稿バッファ | メモリ上。バッファを閉じると終了 |
| この作品 | 同じ作品フォルダの原稿 | `.tategaki/project.json` |
| 全作品の既定値 | 作品/セッション設定のない原稿 | `tategaki-project-default-file`。既定は `user-emacs-directory` 配下の `tategaki/defaults.json` |

優先順位は **セッション > 作品 > 全作品の既定値 > 通常のLisp設定** です。上位の保存値がなければ、従来の `setq` / `setq-local` による設定を使えます。Studio開始時や設定画面を開いた時に保存済み設定を適用します。手動で再読込する場合は `M-x tategaki-project-apply-settings` を実行します。

作品のルートは、原稿から親方向へ探した最寄りの `.tategaki/project.json` があるフォルダです。まだ存在しない場合は原稿のあるフォルダを使います。未保存バッファではそのバッファの `default-directory` を使うため、作品の場所を決めてから作品設定を保存してください。

`[保存]` は**編集・適用した項目だけ**を選択した保存先へ書き込みます。同じ設定画面で保存先を変更すると、その画面で編集した項目を新しい保存先にも保存できます。現在と同じ寸法を別の保存先へ保存したい場合も、`[寸法を適用]` を押してから保存できます。作品のタイトルを表示したまま既定フォントだけを保存しても、そのタイトルを全作品の既定値へコピーしません。表示プレビューは本文、Undo履歴、原稿の未保存マークを変更しません。

`[元に戻す]` は設定画面を開いた時点へ戻します。既に設定を保存した後なら、この操作自体が新しい未保存変更になります。閉じる時に未保存変更があれば `[保存して閉じる]` / `[保存せず閉じる]` / `[戻る]` を選べます。保存せず閉じる場合は最後に保存した状態に戻ります。

作品JSONの例です。メタデータは本文へ挿入しません。

```json
{
  "schema_version": 1,
  "title": "夏の終わり",
  "author": "山田花子",
  "language": "ja",
  "identifier": "urn:novel:summer",
  "settings": {
    "manuscript-size": [20, 20],
    "manuscript-grid": true,
    "character-spacing": 2,
    "ai-enabled": false
  }
}
```

JSONはデータとして読み、Lispとして評価しません。未知の設定名や不正な値は適用しません。壊れたJSONでも原稿は開けますが、そのファイルへの保存は拒否して元ファイルを保護します。問題を修復する前にファイルを別名で退避し、必要なら `tategaki-project-last-error` を確認してください。

## 履歴と前回の位置

Studioでは保存時とidle時に、本文とは別の場所へ履歴を保存します。未保存の本文も対象です。同じ本文が続く場合は履歴項目を追加せず、過去と同じ内容はSHA-256で同じスナップショットファイルを再利用します。

保存先の既定は `~/.local/share/my-tategaki/history/` です。`XDG_DATA_HOME` があればその配下を使い、`tategaki-history-directory` で変更できます。文書ごとの `manifest.json` と `snapshots/<SHA-256>.txt` に保存します。

`[履歴]` から旧稿を開く、現在の原稿と比較する、編集可能なコピーとして復元する操作ができます。**復元は常に別バッファ**で行い、現在の原稿を自動で上書きしません。コピーを残す時は名前を付けて保存してください。手動取得は `M-x tategaki-history-snapshot`、コピー復元は `M-x tategaki-history-restore-as-copy` です。

設定の `[自動履歴]` で停止でき、保存間隔を `[保存時のみ]` にするとidle保存だけを停止します。履歴は通常のファイル保存やバックアップの代わりではなく、現在は自動で古い履歴を削除しません。

原稿の保存時やStudio終了時には、カーソル/マーク、ページ、スクロール、倍率、原稿用紙、見開き、組版、Write/Review、アウトライン状態をセッションファイルへ記録します。開始画面の `[前回の原稿を復元]`、`M-x tategaki-session-open-last`、`M-x tategaki-session-restore` で再開できます。明示保存は `M-x tategaki-session-save` です。

セッションファイルは既定で `~/.local/state/my-tategaki/session.json`（`XDG_STATE_HOME` 対応）です。ここには本文を保存しません。既に開いている未保存バッファがあれば再利用し、ディスクから本文を読み直して置き換えることはありません。設定画面の「このセッションだけ」と、位置を記録するこのセッションファイルは別の機能です。

## 辞書・校正・レビュー

辞書は既存の **Emacs Lookup** とその辞書設定を利用します。語の取得順は選択範囲、カーソル位置の語、手入力です。検索結果は右側に表示し、原稿の位置を保持します。Lookup未導入の場合は必要な設定を案内し、基本編集には影響しません。

`[校正]` または `M-x tategaki-proofread-run` でローカルのルール検査を実行します。括弧、約物連続、全半角/数字表記、登録した表記揺れ/禁止語、文長/段落長、近接した同語、語尾連続、助詞連続、空白を調べます。結果は原稿上のoverlayとクリック可能な一覧です。指摘から本文を変更する操作は自動では行いません。

リアルタイム校正を有効にすると、idle時に変更箇所の近くの軽いルールを検査します。全文検査と同じ範囲ではありません。初期状態ではリアルタイム校正は無効です。表記揺れ/禁止語は次のように登録できます。

```elisp
(setq-local tategaki-proofread-variants '(("出来る" . "できる")))
(setq-local tategaki-proofread-banned-words '("仮の名前"))
```

`M-x tategaki-review` は校正、設定整合性、人物の話し方、時系列、伏線、AI相談、音読、出力状態の入口をまとめます。`[原稿を検査]` はローカルの校正・登録Factの比較・人物の話し方を実行します。画面を開いただけでAIや音読を開始せず、実行していないAI確認や出力検証を成功扱いにしません。

## AI接続とプライバシー

AIは既定で無効です。設定の `Provider: [LM Studio ▼]` など、現在値のボタンをクリックしてOllamaまたはLM Studioを選びます。Endpointが標準URLなら選択したサーバーのURLへ切り替わります。自分で入力したカスタムURLは保持します。`[標準URLを使う]` で選択中のProviderのURLへ戻せます。

Provider項目のない旧設定では、既知の標準ローカルEndpointから接続先名を補完します。明示されたProviderやLispのローカル設定は優先し、独自URLでは推定しません。選んだProviderを今後も使う場合は保存先を選び `[保存]` を押してください。

`[モデル一覧を取得]` を押し、`[一覧からModelを選択]` と `[一覧からEmbeddingを選択]` で用途ごとのモデルを選びます。本文は送らず、AIが無効の状態でも一覧を取得できます。名前の自由入力も可能です。接続先変更時には古い一覧と取得中の応答を破棄します。0件ならサーバー側のモデルを確認してください。一覧APIだけでは用途を判別できないため、embeddingに対応するモデルを作者が選びます。

全providerでOpenAI-compatible APIを使います。Endpointには `/v1` までを指定し、`/chat/completions` を付けません。

| Provider | Endpointの例 | サーバー側の資料 |
|---|---|---|
| Ollama | `http://127.0.0.1:11434/v1` | [OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility) |
| LM Studio | `http://127.0.0.1:1234/v1` | [モデル一覧API](https://lmstudio.ai/docs/developer/openai-compat/models) |
| llama.cpp | `http://localhost:8080/v1` | [llama.cpp server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) |
| OpenAI-compatible | `http://localhost:8000/v1` など、自分で起動した互換サーバーのURL | サーバーの待受ポートとAPI構成に合わせる |

`[接続テスト]` はモデル一覧APIを呼び、本文を送信しません。接続成功は、選択したモデルで生成やembeddingが成功する保証ではありません。モデル未導入、embedding非対応、メモリ不足などは実行時の結果を確認してください。

通常の相談では、選択箇所/現在位置の周辺、検索で見つかった原稿、登録した作品設定や作品時間、資料の一部を送ります。対象にしたコレクションの別原稿・資料も検索候補に含みます。索引作成では原稿の各chunkをembeddingサーバーへ送ります。いずれも明示操作で開始し、原稿を自動で書き換えません。

Novel StudioのAI相談・索引・候補抽出は `localhost` / `127.0.0.1` / `::1` のhttp(s)接続をローカルと判定します。それ以外の接続先では本文送信の都度確認し、既定では自動送信しません。`tategaki-ai-allow-remote` を明示的に `t` に設定すると確認なしの送信を許可するため、通常は `nil` のまま使います。リダイレクトによる接続先の変更には追従しません。既存のCopilot補完はCopilot側の接続・認証設定に従い、このAI設定とは別です。

ローカル判定は**接続先のhost**についてです。サーバー自体のクラウド転送までは判定しません。例えばOllamaはローカルサーバー経由のクラウドモデルも提供しているため、完全にローカルで使う場合はサーバー側でもローカルモデルを選んでください。[Ollamaの接続方式](https://docs.ollama.com/api/openai-compatibility)

APIキーが必要な接続では、`tategaki-ai-api-key-function` にキーを返す引数なしの関数を設定します。例えば `auth-source` から取得する関数を使います。キーを作品JSONや原稿に書く必要はありません。

Lispで現在の原稿だけを設定する場合の例です。モデル名はプレースホルダーです。

```elisp
(require 'tategaki-ai)
(setq-local tategaki-ai-enabled t)
(setq-local tategaki-ai-provider 'ollama)
(setq-local tategaki-ai-endpoint "http://localhost:11434/v1")
(setq-local tategaki-ai-model "導入済みのチャットモデル名")
(setq-local tategaki-ai-embedding-model "導入済みのembeddingモデル名")
```

Embedding Modelを空欄にするとModelと同じ名前を使います。多くのチャットモデルはembeddingに対応しないため、意味索引用にはembeddingモデルを別途指定してください。現在はチャットとembeddingで共通のEndpointを使います。

## 意味索引・検索・Assistant

1. AI設定を完了し、原稿を保存します。
2. `[AI]` でAssistantを開き、`[意味索引を作成]` または `M-x tategaki-semantic-index` を実行します。
3. `[検索]` または `M-x tategaki-semantic-search` で関連箇所を探します。結果のクリックで原稿へ移動します。
4. Assistantの `>` に質問を入力し、`RET` または `C-c C-c` で送ります。プリセット、選択範囲、人物についての相談もボタンから選べます。`C-c C-k` / `[取消]` で相談を取り消します。 AIペイン上部の `[閉じる]` または `q` / `C-c C-q` は処理中の相談を中止して原稿へ戻ります。会話と入力中の質問は再度開くと続けられ、設定など他のペインは残ります。

索引は段落と場面/章の手掛かりを使って原稿を分割し、長い段落は既定800字で分割します。章・場面・原稿位置・ハッシュに加え、採用済みの人物名・別名の文字列出現、登録Sceneの登場人物/POV、採用済み時系列をタグに反映します。名前の出現は言及の印であり、その人物が情報を知ったことを意味しません。未登録の視点や日時を自動で確定しません。`tategaki-semantic-index` の対象は**現在の原稿バッファ**で、別原稿との横断検索には後述のコレクションを使います。

索引は `.tategaki/index/<原稿パスのハッシュ>.json` に保存します。原稿内容、Endpoint、Embedding Modelが一致する場合だけ再利用します。原稿を書き換えたら索引を再作成してください。未作成、古い索引、embedding通信失敗では **語句検索（lexical）へ切り替え**、結果に検索方式を示します。AIを無効にしたままでもこの語句検索を使えます。

Assistantは回答を「原稿から確認できること」「推測」「不明」「参照箇所」に分けるようモデルへ指示します。これは回答の正確性を保証するものではありません。`[第3章:1234]` のようなラベルは、実際に渡した出典に一致するものだけがクリック可能になります。数字は**行番号ではなくEmacs原稿位置**です。回答待ちに原稿が変わった場合や参照後に内容が変わった場合は、古い位置へ移動せず再検索を求めます。

`M-x tategaki-ask-region` は選択範囲、`M-x tategaki-ask-character` は指定人物について相談します。人物相談は現在位置を上限とし、さらに**その人物の `known-by` 付きFactの出典範囲、または採用済みSceneの `visibility` で許可した引用範囲だけ**を本文の文脈にします。SceneのPOVや登場人物に含まれるだけでは許可しません。未注釈の周辺本文・章名・資料・別原稿・一般の時系列を人物の知識として混ぜず、許可した情報がなければ不明として回答するよう指示します。「この時点」などの一般質問にも現在位置による制限が入ります。

この上限は原稿上の数値位置と作者が許可した出典範囲による絞り込みです。登場人物が描写から本当に何を認識したか、回想・予告・嘘・伝聞を完全に理解する仕組みではありません。Sceneの範囲を広げるにはその範囲自体の正確な引用が必要で、章・明示的な場面区切りをまたぐ範囲は使いません。時点を制限する質問には、時点の定まらない資料を混ぜません。

`M-x tategaki-knowledge-compare` またはAssistantの `[読者との知識差]` は、現在位置までの登録Factを「読者だけ」「人物だけ」「両方」に分け、出典へ移動できる一覧を表示します。Factの `known-by` に読者を含める場合は `reader` を指定します。未登録の情報は不明で、記録がないことから人物が知らないと断定する検査ではありません。

## 作品資料

作品の `.tategaki/resources/` へ `.txt` / `.md` / `.org` を置くと、通常の相談時に語句検索で関連箇所を収集します。原稿の引用は `[章:位置]`、資料は `[資料:ファイル名:位置]` と表示して区別します。

このディレクトリ経由で対応するのは直下のプレーンテキストです。PDF、Word、画像、OCR、サブフォルダの再帰検索は対象外です。シンボリックリンクを除外し、最大100ファイル、既定では1ファイル2MB/一度に合計4MBまで読みます。資料も、選択したAIへの文脈に含まれる場合は送信対象です。

複数原稿や資料を横断して検索するには、`M-x tategaki-corpus` で**原稿・資料コレクション**を開きます。

1. `[原稿を登録]` / `[資料を登録]` から対象のローカルファイルを個別に選びます。登録時はパスを保存するだけで、本文の読込やAI送信は行いません。
2. `[対象]` / `[除外]` で利用するファイルを選び、必要なら `[意味索引を更新]` を押します。対象ファイルの本文を設定したembeddingサーバーへ送ります。
3. `[検索]` / `M-x tategaki-corpus-search` で横断検索し、結果のファイル名・章・位置から出典へ移動します。`[中止]` で処理を止められます。

登録は `.tategaki/corpus.json`、embeddingは `.tategaki/corpus-index.json` に保存します。除外や登録解除は元ファイルを削除しません。索引が未作成/古い、AIが無効、embeddingが失敗した場合は語句検索を使います。編集中のファイルは未保存のバッファ本文を優先し、内容・対象一覧・接続先/モデルが途中で変われば古い結果を破棄します。

通常のAssistant相談では、有効なコレクションも検索し、現在の原稿や周辺本文と合わせて文脈上限まで参照します。別原稿の引用は `[原稿:ファイル名:章:位置]`、資料は `[資料:ファイル名:位置]` です。同名ファイルなどでラベルが重なる場合は `#2` などを付けて出典を区別します。人物相談と「この時点」などの位置を制限する質問では、別原稿・資料の検索を行いません。別ファイルにも原稿と同じ内容ハッシュの検証が入り、書き換わった出典へのジャンプは拒否します。

コレクションへ登録して `[除外]` にした資料は、`.tategaki/resources/` 内にあっても通常相談から除外します。質問の送信前と回答待ちにも登録内容・参照ファイルの変化を確認し、古い文脈の送信や出典リンクの有効化を防ぎます。

コレクションもテキストとして読む機能で、PDF/Word/OCRの変換器は含みません。既定のファイル上限は5MiB（`tategaki-corpus-max-file-size`）です。フォルダ全体の自動登録や再帰走査は行いません。

## 人物・設定・時系列・伏線

`[人物]` / `M-x tategaki-world` ではCharacter、Place、Organization、Object、Event、Relationship、Fact、Sceneを登録します。状態は `observed`（本文で観察）、`inferred`（推測）、`author-confirmed`（作者確認）、`rejected`（却下）を区別します。

`M-x tategaki-world-add` で作者確認済みの項目を登録できます。Factでは対象、属性、値、同一時点/場面を区別するcontext、知っている人物を指定します。Relationshipで属性 `alias`、正式名と別名を登録すると、採用済みの別名を含めた初出や人物の言及を扱えます。名寄せ候補を自動で確定したり、文字列の似た別人を統合したりしません。

Sceneでは原稿の引用範囲に対して、視点人物 `pov`、登場人物 `characters`、引用内容を知る人物 `visibility` を別々に登録します。人物の知識獲得は `knowledge:話題` のFactに記録でき、抽出候補では見た/聞いた/読んだ等の獲得経路も保持します。人物カードには採用済み別名を含む初出と、原稿の登場箇所へのリンクを表示します。

`M-x tategaki-world-extract` は選択範囲または現在の段落、`M-x tategaki-world-extract-all` は現在の原稿全文からAI候補を抽出します。全文は既定5000字を目安に分割して順次処理し、進捗と中止操作を表示します。根拠の引用が実際の処理範囲に一致した項目だけを候補にし、モデルが返したIDや採用済み状態は信用しません。全処理が成功し原稿・AI設定が変わっていない場合にまとめて保存します。候補は常に `inferred` で入り、作者が確認するまで確定Factとして使いません。

`M-x tategaki-world-check` は同じcontextにある登録Factを比較します。年齢、日付/曜日、場所、左右、色、所有、関係、呼称、生死、知識、一人称などの値の不一致を提示します。原稿全体を読んであらゆる矛盾を自動理解する検査ではありません。状態変化を違う場面として扱う場合はcontextを分けます。本文の観察には出典が変わっていないことを要求し、古い出典へ無条件に移動しません。

`M-x tategaki-timeline` では場面を原稿順/作品時間順で確認し、日時を `exact` / `relative` / `inferred` / `unknown` として登録します。相対日時は基準場面と分単位の差で表し、循環参照や基準不明は未解決になります。`[本文全文から日時候補]` / `M-x tategaki-timeline-extract`、または選択範囲のボタンで明示日時・翌日等の候補を抽出できます。日時状態とは別に採用状態を管理し、相対日時の採用には先に基準場面の採用が必要です。不明な年を現在年で補わず、原稿の日時を全自動で確定しません。

`M-x tategaki-foreshadow` では作者が伏線を登録し、未回収/回収済み/候補/却下を管理します。`[本文全文から配置・回収候補]` / `M-x tategaki-foreshadow-extract`、または選択範囲のボタンで配置と回収の候補を抽出できます。配置候補を採用してから、回収候補の採用時に対応する未回収の伏線を作者が選びます。出典が現在の原稿と一致し、回収箇所が配置箇所より後であることを確認します。モデルの候補だけでは既存の伏線を回収済みにせず、作者による対応付けと両方の引用を保存します。

`M-x tategaki-voice` は人物の話し方を扱います。作者が選択範囲を人物の台詞例として登録し、一人称・二人称・語尾・避ける語・文長・敬語の設定を指定します。文字列や文長等のローカル比較で候補を示すもので、文体の良し悪しや話者の自動確定は行いません。原稿変更後も登録した旧台詞の例文は残ります。

頻出表現は固定の語彙一覧ではなく、台詞の見本から3〜12文字の反復を抽出します。句読点等で区切った複数の句に出る表現を数え、同じ出現数なら長い表現を優先します。表示する数は出現した句の数です。形態素解析ではないため、単語の途中からの候補もあり得ます。

通常の `「台詞」` にも、前後の「花子は言った」「と太郎は答えた」といった描写や、登録見本の反復表現・一人称から話者候補を示します。根拠のない台詞は「不明」、根拠が競合する場合は複数候補のままです。「名前として採用」を押した台詞だけがその人物の見本になります。採用前の候補を口調検査に混ぜず、原稿が変わった古い候補は採用を拒否して更新を求めます。話者の描写が省略された会話、入れ子の鉤括弧、皮肉や引用の真の発話者を網羅的に判定する機能ではありません。

これらは `.tategaki/world.json`、`timeline.json`、`foreshadow.json`、`voice.json`、`voice-profiles.json` に保存します。名前を付けていない原稿ではメモリ上の情報となるため、保存する作品を決めてから登録してください。

## Reader・音読・別案比較

`M-x tategaki-reader-mode` は、本文を読み取り専用にし、診断表示や補助画面を隠して文庫本風の見開きにします。既定の版面は40字×17列です。`SPC` / `n` が次、`p` / `DEL` が前、`q` / `[閉じる・執筆に戻る]` で終了します。終了時には元の表示設定、診断の表示状態、ウィンドウ配置と編集状態を戻します。

音読は **macOSの `say`** がある場合に使えます。`[音読]` / `M-x tategaki-tts-play` は現在位置から読み、`tategaki-tts-read-region` は選択範囲を読みます。`tategaki-tts-pause` で一時停止し、`tategaki-tts-resume` またはplayで再開、`tategaki-tts-stop` で停止します。設定画面の `[利用可能なVoice]` で実機の声を選べます。

速度は既定180 words/minuteに対する倍率です。音読はローカルプロセスへ標準入力で渡し、本文をコマンドライン引数やログに残しません。現在読み上げている**文単位**のoverlayを表示し、単語単位の正確な音声同期は行いません。原稿を編集すると、古い位置の読み上げを続けず停止します。

固有名詞の読みは本文を変えずに設定できます。

```elisp
(setq-local tategaki-tts-pronunciations '(("小鳥遊" . "たかなし") ("四月一日" . "わたぬき")))
```

`M-x tategaki-diff-buffers` は旧稿と新稿のコピーを縦書きで並べ、変更行を色分けします。`n` / `p` で差分を移動し、`q` で戻ります。履歴からの比較も同じ機能を使います。`diff` コマンドが必要で、比較単位は行です。字単位の変更追跡や自動マージではありません。

`M-x tategaki-scene-branch` は現在の原稿を履歴へ記録してから、選択範囲（未選択時は全文）の編集可能な別案コピーを作ります。別案は未保存バッファで、原稿への自動反映やGitブランチの作成は行いません。必要な案を個別に保存・比較してください。

## 作品メタデータを使って出力する

設定画面で保存したタイトル・著者名・言語・識別子は、EmacsからのDOCX/PDF/EPUB/HTML出力に共有します。優先順位は、明示的なexport override、作品メタデータ（現在のセッションの変更を含む）、`tategaki-export-metadata`、ファイル名等の既定値です。

`[出力]` / `M-x tategaki-export`、全形式なら `M-x tategaki-export-all` を使います。原稿の表示フォントや原稿用紙設定は画面用です。提出物の用紙やフォント等は出力profileで別途指定します。実際のファイル生成には従来のDocker出力環境が必要です。[出力ガイド](docker-export-guide.md)

## 動作確認と現在の範囲

テストは設定プレビューの本文/Undo/modified不変、設定保存と再読込、scopeの独立、壊れたJSON保護、履歴と位置復元、校正、AI応答/古い参照の拒否、世界設定、Reader、比較、非同期TTSを対象にしています。GUIではクリックから設定・縦書き描画までを確認します。実行結果と実機確認範囲は[検証記録](novel-studio-validation.md)に記載しています。

実機ではLM StudioのローカルGemma 4による日本語chatと768次元embeddingを合成原稿で確認し、人物に許可した知識がない質問で「不明です」と回答することを確認しました。世界設定・日時・伏線の実モデル抽出と、作者採用による日時解決・伏線回収も検証しています。Docker出力はEPUBとHTMLを作品設定から実生成し、EPUBCheckのエラー・警告0件、Apple Booksで縦書き・ルビ・目次移動を確認しました。既存のDocker統合8ケースではTXT/DOCX/PDF/EPUB/HTMLの実生成と構造検証も通りました。

これらは回答品質やすべての閲覧アプリの表示を保証するものではありません。音読も全音声の発音品質を保証しません。任意依存が使えない場合はその機能だけが案内を表示し、通常の執筆は続けられます。モデル名、実機操作、未検証の組合せは[検証記録](novel-studio-validation.md)を確認してください。
