# Novel Studio 利用ガイド

Novel Studioは、縦書きの原稿と、章の目次・履歴・校正・作品資料・AI相談を一緒に使うための画面です。このページはGitHub上でも読める開始ガイドです。機能別の詳しい手順は、同梱の[日本語マニュアル](index.html)へ統合しました。

## 最初の原稿を書く

Emacsの設定へ、実際の配置先を指定します。

```elisp
(add-to-list 'load-path (expand-file-name "~/src/my-tategaki"))
(require 'tategaki)
```

1. `M-x tategaki-studio`を実行します。開いているテキスト原稿を使うか、開始画面の［新しい小説を書く］［原稿を開く］を選びます。
2. 組版表示を使うときは、本文ウィンドウで`M-x tategaki-typeset-edit`を実行します。その後［⚙設定］で文字の大きさと用紙を調整します。
3. 設定の保存先を選び、［保存］→［閉じる］で原稿へ戻ります。
4. 本文を書き、［原稿］→［保存］または`C-x C-s`でファイルへ保存します。

最初に作品用のフォルダを用意して本文を置くと、作品設定や資料の保存場所を揃えられます。設定の保存は本文の保存とは別です。

## Write / Review と操作

Writeは原稿と表示中の目次を残す画面、Reviewは補助ペインを使って推敲する画面です。上部に見当たらない操作も［原稿］メニューから開けます。［閉じる］は各ペインの上部にあり、通常はそのペインだけを閉じて本文へ戻ります。

| 操作 | キー |
|---|---|
| 原稿メニュー / 設定 | `C-c s m` / `C-c s s` |
| Write / Review | `C-c s w` / `C-c s r` |
| 目次を開く・閉じる | `C-c s o` |
| 履歴 / 辞書 / 校正一覧 | `C-c s h` / `C-c s d` / `C-c s p` |
| AI相談 / 関連箇所検索 | `C-c s a` / `C-c s /` |

Studioを終了するときは［原稿］→［Studio を終了］を選びます。縦書き自体を終了するには`C-c C-c`を使います。[画面とペインの説明](manual/studio.html)

## 執筆中の目次・アウトライン

本文へ次のように見出しを書き、［目次］を開きます。

```text
# 第一章
本文を書く。
## 第一節
節の本文を書く。
```

見出し名をクリックすると本文へ移動し、三角をクリックすると節を折りたためます。本文の現在位置と、見出しの追加・変更に追従します。`#第一章` / `##第一節`のような日本語の番号付き見出しは空白を省いても認識します。任意のタイトルは`# プロローグ`のように空白を入れます。[目次の詳しい操作](manual/writing.html#outline)

## 設定と保存先

原稿用紙はプリセット、縦字数・列数の自由指定、フリーから選べます。自由指定は各1〜200の整数を入力して［寸法を適用］します。フリーは固定の字数・列数を使いません。

文字を大きくするときは［＋］、用紙全体を見渡すときは［用紙全体を画面に収める］を使います。固定用紙では縦の字数が画面高に収まる大きさが上限です。[文字サイズと用紙](manual/studio.html#paper)

設定の優先順位は **このセッションだけ → この作品 → 全作品の既定値 → 通常のLisp設定** です。［保存］ではその設定画面で編集・適用した項目を保存します。本文・Undo・本文の未保存マークは変更しません。[保存先と取り消し](manual/studio.html#scope)

## 履歴と前回の位置

履歴は取得時点の本文、セッションはカーソル位置や画面状態を記録します。履歴からの復元は別コピーで、取得前の変更までは戻せません。前回位置の復元だけでは未保存本文は復元しません。一度もファイル名を付けていない原稿は、再起動後の履歴UIへ自動で結び付かないため、終了前に名前を付けて本文を保存してください。

［履歴］では旧稿を開く・比較する・別コピーへ復元する操作ができます。［原稿］からReaderや音読を開き、書いた文章を読み返せます。[履歴・比較・再開・Reader・音読](manual/history.html)

## AI接続とプライバシー

AIは既定で無効です。使う場合だけ、OllamaやLM Studioのサーバーを起動し、設定のAI欄で有効にします。

1. Providerを選び、［標準URLを使う］で接続先を合わせます。独自URLは明示的に入力します。
2. ［モデル一覧を取得］を押し、会話用のModelと意味検索用のEmbedding Modelをそれぞれ選びます。
3. ［接続テスト］で疎通を確かめ、設定を保存します。
4. ［原稿］→［AI に相談］から質問します。参照リンクで回答の根拠を確認します。

一覧はモデルの用途を自動判定しません。埋め込みを使う場合は対応モデルを選んでください。意味索引が未作成・古い場合は語句検索を使います。送信対象は操作によって異なり、外部の接続先への本文送信には確認が入ります。[AI・検索・資料の手順と送信範囲](manual/ai.html)

## 人物・設定・時系列・伏線

人物、場所、Fact、Sceneなどを作品データとして登録できます。AI抽出は出典付きの候補を作り、作者が採用・却下します。時系列、伏線、話し方、読者と人物の知識差も登録情報と原稿の根拠を参照します。小説全体の意味を理解して設定の正しさを保証する検査ではありません。[作品資料の整理と候補の扱い](manual/world.html)

## 出力

Docker環境を準備した後、［原稿］→［出力］でTXT・DOCX・PDF・EPUB・HTMLへ書き出します。処理開始時の未保存本文を含むスナップショットを使います。画面を閉じても出力は続くため、止めるときは取消操作を使います。[環境構築・出力・形式ごとの制限](manual/export.html)
