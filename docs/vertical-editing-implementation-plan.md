# 縦書き編集の機能拡充・実装計画

作成日: 2026-09-26  
状態: 計画。各項目の実装着手・完了を示すものではない。

## 目的と比較の基準

`tategaki-mode` を、日常的な日本語の執筆から長文の推敲まで使える縦書き編集環境へ育てる。今回の比較対象は、ポメラ DM250、縦式、TATEditor、および日本語組版の要件である。製品ごとの機能差があるため、以下をすべての縦書きエディタに共通する必須機能とは扱わない。

優先するのは、検索・校正の表示、入力応答性、自然な日本語の文字組み。原稿管理や出力はその後に拡充する。Emacs にある検索、保存、Undo、章管理、辞書連携等は既存機構を利用する。

## 現在の到達点

作成時に読み直した `README.md` と、調査時に確認した描画処理を基準とする。開発が並行して進んでいるため、各段階の着手時に現状と差分を再確認する。

以下は既存機能として維持し、再実装しない。

- 元のテキストバッファを使った入力、削除、選択、コピー、保存、Undo。
- 上から下・右から左への表示、実カーソルと表示位置の対応。
- IME 未確定文字の縦表示、文節の強調、確定・取消、候補位置の補正。
- Copilot の提案と Corfu のプレビューの縦表示、Corfu 候補一覧の位置補正。
- 上下左右の余白、文字間・列間、フォントの調整。
- 画面方向への移動キー設定。
- `C-v` / `M-v` 等による画面単位のページ移動、数値引数、短い最終ページとの往復。
- 対象ウィンドウへの表示限定、通常バッファとの分離、narrowing。

現在のページ移動はウィンドウに収まる縦列を基準とする。印刷用の用紙サイズ・版面・ページ番号とは別に扱う。

既存テストの実行方法と直近の結果は `README.md` を参照する。本計画書の作成時には、テストの再実行はしていない。

## 守る条件

1. 表示のために本文を書き換えない。縦書き約物、仮入力、候補、ルビの表示文字を保存内容に混入させない。
2. 実際の編集、IME の確定、補完の採用、Undo は既存の編集機構に任せる。
3. 通常バッファ、ミニバッファ、別ウィンドウ・別フレームへ設定や表示を漏らさない。
4. モード終了時に、表示、フック、キー、ローカル設定を復元する。
5. 元の文字位置、表示上の文字、カーソル、選択範囲の対応を保つ。
6. optional なパッケージや出力ツールがなくても、基本的な縦書き編集は使えるようにする。
7. GUI の座標や IME の操作性を、バッチテストの成功だけで検証済みとしない。

- [ ] 1千・1万・10万・20万字の再現可能な計測用テキストを用意する。多数の短い段落と、長い単一段落を含める。

**完了条件:** 未確認項目、変更対象、計測環境、現状の性能を記録し、基本機能の基準テストが再現できる。描画方式が未確定の機能は、実装見積もりに含める前に技術検証を行う。

## 段階1: 毎日の執筆で困る表示と応答性を整える

### G01: 検索・校正の強調表示

**方針:** 本文の文字位置にある表示属性を、縦書きの対応する表示セルへ反映する。検索処理そのものを置き換えない。初期対象は isearch、lazy-highlight、query-replace、本文の face とし、校正パッケージは個別に対応範囲を確認する。

- [ ] 現在の選択範囲、IME、補完、検索結果、本文の装飾の優先順位を定義する。
- [ ] 元の text property と overlay の face を取得し、表示対象の範囲だけに適用する。
- [ ] 本文が変わらず overlay のみ変わった場合にも更新する。
- [ ] 不明な `display`、`before-string`、`after-string` を無条件に複製しない。文字列を追加する機能は個別の連携対象とする。

**完了条件:** 縦列・ページをまたぐ検索結果と置換対象が見え、次の一致箇所へ移動できる。検索終了で強調が消え、本文と Undo に余分な変更がない。既存の選択・IME・補完の強調が壊れない。

### G02: 長文性能

**方針:** 編集された段落と、その変更で影響を受ける配置を更新する。文字幅の計測、段落のレイアウト、可視ページの描画を分離してキャッシュする。ページ数の計算が入力を長時間止めないようにする。

- [ ] 入力から再描画までの時間、初回表示時間、ページ移動時間、メモリ量を測る。
- [ ] フォント・余白・文字間・禁則設定等によるキャッシュ無効化条件を定義する。
- [ ] 局所編集と、先頭への大きな貼り付け・全置換等の広い変更を分けて扱う。
- [ ] キャッシュと全文再計算の結果が一致することを検証する。

**完了条件:** 同じ環境とテキストで変更前後を比較でき、通常の局所編集で全文の文字幅計測を繰り返さない。10万字の通常入力で再描画までの p95 を100ms以内とする暫定目標を置く。これは実測結果ではなく設計目標であり、達成状況と未達理由を記録する。20万字でも保存内容・位置対応・Undo を保つ。

## 段階2: 見た目の一文字と元テキストを対応させる

### G03: 複数文字からなる表示単位

**方針:** 一つの表示セルに、元バッファの開始・終了位置と表示する文字列を持たせる。結合文字、異体字セレクタ、絵文字の連結列、後続の縦中横・ルビの基盤にする。

- [ ] 結合濁点、異体字セレクタ、絵文字修飾子、ZWJ を含む例を用意する。
- [ ] 元テキストとコピー・保存結果を正規化や置換で変えずに表示する。
- [ ] クリック、左右上下の移動、選択境界を元の文字範囲へ対応させる。
- [ ] セル内の位置を明示的に編集する操作も可能にし、既存の論理的な文字移動・削除の意味を不用意に変えない。

**完了条件:** 見た目の一文字が複数列へ分裂しない。表示セルから原文へ戻る対応が一意に定まり、セルの途中へ検索・IME・補完が関わる場合にも文字が失われない。

## 段階3: 日本語の基本的な文字組み

### G04・G05: 禁則、分割禁止、列末の調整

- [ ] 最初に行頭・行末禁則と分割禁止を実装する。例: 句読点・閉じ括弧、開き括弧、対の三点リーダー・ダッシュ。
- [ ] 禁則文字の集合と強さを設定できるようにし、基準を JLReq と照合する。
- [ ] 追い出し・追い込み・ぶら下げの採用順と適用範囲を決める。まず単純な方式で正しく動かし、細かな字間調整を追加する。
- [ ] 極端に短い列や禁則文字が連続する場合の終了条件・代替配置を設ける。

**完了条件:** 原文を変えずに禁則を適用できる。列末付近の編集、ページ境界、リサイズ、Undo でも文字が欠落・重複せず、無限の再配置が発生しない。禁則により移動した文字でもカーソルとクリック位置が一致する。

### G06・G07: 縦中横、欧文、約物

- [ ] 縦中横は、選択した範囲への明示指定から始める。数字2桁や `!?` の自動判定は設定で選べるようにする。
- [ ] 縦中横の範囲・表示幅・縮小方針と、セル内のカーソル・選択の扱いを決める。
- [ ] 立てる英字、回転する欧文、縦中横を区別する。URLや長い英単語の扱いも定義する。
- [ ] 約物の縦書き字形・配置、長音記号、括弧、三点リーダーを複数フォントで確認する。
- [ ] ネイティブの文字表示、フォントの縦書き字形、必要な場合の画像描画を比較する。GUI・端末それぞれの代替表示を明示する。

**完了条件:** 例文中の数字・英語・約物が意図どおりに表示され、本文の文字は変わらない。複数文字をまとめたセルでも挿入・部分選択・検索が成立する。表示できないフォントで黙って文字を失わない。

## 段階4: ルビ・傍点・傍線

### G08・G09: 注記の表示と編集

**方針:** 初期対象を青空文庫形式の限定した記法に絞り、対応記法を文書化する。文字列として入力した注記と、表示上の親文字・注記を対応させる。入力補助コマンドが記法を追加・削除する操作は、通常の本文編集として Undo 可能にする。

- [ ] ルビの親文字範囲、読み、表示サイズ、配置をモデル化する。
- [ ] 短いルビから実装し、親文字を超える長いルビ、列・ページ境界の扱いを定義する。
- [ ] 記法を見せる編集表示と、組版した表示を切り替えられるようにする。
- [ ] 未完成・不正な記法は原文表示に戻し、入力途中の文字を隠さない。
- [ ] 傍点・傍線と、ルビ・選択・検索・IMEが重なる場合の配置を確認する。

**完了条件:** 注記記法を保った保存・再読込ができる。親文字・読みをそれぞれ編集でき、注記は本文の文字数やページ計算で定義した扱いに従う。横書き表示との往復で記法が失われない。

## 段階5: ポメラ等を参考にした原稿管理

### G10・G11: 原稿用紙・固定版面・ページ情報

- [ ] ウィンドウに合わせた表示と、文字数×行数で固定した原稿表示を分ける。
- [ ] 20字×20行、40字×30行等をプリセットとして選べるようにする。
- [ ] 原稿用紙の罫線、現在ページ・総ページ数、指定ページへの移動を追加する。
- [ ] 小さいウィンドウでは縮小または部分表示を選び、勝手に原稿の改ページ位置を変えない。
- [ ] 見開き・段組みは固定版面の計算が安定してから追加する。

**完了条件:** 画面ページと原稿ページの意味が明確で、文字の追加・削除に応じて原稿ページ数が更新される。既存の画面ページ移動を保つ。ズームと原稿の版面変更を区別できる。

### G12: 文字数・枚数・目標

- [ ] 全文、選択範囲、章の文字数を表示する。
- [ ] 空白・改行・ルビ記法を数える規則を選択・表示する。
- [ ] 「文字数÷400による換算」と「原稿用紙へ配置した実際の枚数」を区別する。
- [ ] 目標文字数と残り文字数は任意表示にする。

**完了条件:** 同じ数え方なら通常の Emacs 側の集計と一致し、原稿用紙の空きマスを含む枚数との違いが説明される。集計で入力応答を悪化させない。

### G13・G14: アウトライン・入力支援

- [ ] Org / outline / imenu 等を使い、見出し一覧からの移動を接続する。
- [ ] 折りたたみで非表示になった本文を縦書きレイヤーが再表示しないようにする。
- [ ] 章の並べ替え後に表示・ページ・文字数を更新する。
- [ ] 自動一字下げ、会話文の字下げ調整、括弧補完を既存の入力設定と比較する。重複して挿入しない。
- [ ] 文書ごとの表示設定・再開位置は既存のローカル変数や保存機構を利用し、適用範囲を明確にする。

**完了条件:** 通常表示で行った章移動・折りたたみと縦表示の内容が一致する。設定を無効にすれば通常の入力に戻り、変更が他のバッファへ漏れない。

## 段階6: PDF・印刷・EPUBへの出力

### G15: 原稿を外へ渡す

- [ ] 最初に PDF 出力を試作し、出力エンジンと依存関係を決める。画面の装飾用文字列をそのまま本文として書き出さない。
- [ ] 原文と解析済みの注記・版面設定から出力する。フォント、用紙、余白、段組み、ページ番号、柱を指定できるようにする。
- [ ] EPUB は縦書き方向、ルビ、縦中横、目次、閲覧ソフトでの差を検証する。
- [ ] 画面と出力で完全に同じ改ページを保証するかを明示する。異なる組版エンジンを使う場合は、出力プレビューを確認手段にする。

**完了条件:** PDF の文字欠け・注記の衝突・ページ末の欠落がなく、文字を抽出して原稿と照合できる。EPUB は構造検証と実際の閲覧ソフトで確認する。出力ツールが未導入でも編集機能は動く。

## 段階7: 用途別の拡張

### G16: 脚本・台本

人物名、台詞、ト書き、シーン見出しの規則を定義し、原稿の構造を扱う既存モードとの連携を検討する。通常の文章編集を維持したまま、専用の体裁を選べるようにする。

**着手条件:** 実際に使う台本形式とサンプル原稿が決まっていること。

**完了条件:** 台詞等の挿入・削除・章移動後も位置と字下げが保たれ、元のテキストと出力結果を照合できる。

## 検証と移行

各段階は「調査 → 小さな試作 → 実装 → 移行・互換性確認 → 自動テスト → 実画面確認 → 文書更新」で進める。

| 検証層 | 確認すること |
|---|---|
| レイアウト | 文字範囲、禁則、注記、ページ境界、再計算とキャッシュの一致 |
| 編集 | 挿入・削除・部分選択・コピー・保存・Undo・narrowing |
| GUI | 実カーソル、クリック、選択、文字拡大、リサイズ、余白・間隔、小さい画面 |
| 入力連携 | IME文節移動・確定・取消、Copilot全文・部分採用、Corfu選択・取消、候補ウィンドウ |
| 分離と後始末 | 同じ文書の別ウィンドウ、通常バッファ、モード終了、バッファ終了 |
| 性能 | 通常入力、大量貼り付け、先頭編集、全置換、ページ移動、メモリ量 |
| 出力 | PDF実ページ、抽出文字、EPUB構造と実機表示 |

- GUI試験は専用プロセス・専用バッファで行い、編集中のユーザー原稿に試験用の文字を入れない。
- Copilot連携試験では、表示・採用の試験に生成リクエストを必要としない。
- 既存設定の既定値と通常操作を保ち、組版・入力補助の新設定はバッファ単位で解除できるようにする。
- 検証結果には実行環境、対象テスト、成功・失敗・スキップ、未確認事項を記録する。
- 未確認の候補ウィンドウや出力結果を、内部座標のテストだけで確認済みにしない。

## 推奨する着手単位

最初の変更は **G01 の isearch / query-replace 表示対応**に限定する。原文の編集機構を維持したまま使い勝手を改善でき、以後の注記や校正表示にも役立つ。G02 の現状計測は独立して実施できる。

その後、複数文字をまとめる表示モデルを固め、禁則・縦中横、ルビ、原稿管理、出力の順に進める。描画方式の検証で制約が判明した場合は、対象機能の範囲と代替表示を計画へ反映する。
