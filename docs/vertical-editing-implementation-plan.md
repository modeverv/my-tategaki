# 縦書き編集の機能拡充・実装計画

作成日: 2026-09-26  
更新日: 2026-09-27

状態: G01〜G12の以下の対応範囲を実装し、個別ERT・専用GUIで確認済み。追加でG13の見出し一覧・移動、G14の入力支援、G16の簡易脚本形式を実装した。チェック欄は確認した具体的な範囲を示す。全回帰結果・性能測定・残る制約は[検証記録](vertical-typesetting-validation.md)に集約する。

## 目的と比較の基準

`tategaki-mode` を、日常的な日本語の執筆から長文の推敲まで使える縦書き編集環境へ育てる。今回の比較対象は、ポメラ DM250、縦式、TATEditor、および日本語組版の要件である。製品ごとの機能差があるため、以下をすべての縦書きエディタに共通する必須機能とは扱わない。

優先するのは、検索・校正の表示、入力応答性、自然な日本語の文字組み。原稿管理や出力はその後に拡充する。Emacs にある検索、保存、Undo、章管理、辞書連携等は既存機構を利用する。

## 現在の到達点

既存の編集機能を維持したまま、検索faceの反映、独立した組版モデル・SVG描画、固定版面・統計のモジュールを追加した。操作・設定・対応する注記記法は [README](../README.md) を参照する。組版モデルのERT31件、原稿・統計のERT29件、組版編集の専用GUI9件が成功した。各段階の完了条件と、確認した対応範囲を区別して以下に記録する。

以下は既存機能として維持し、再実装しない。

- 元のテキストバッファを使った入力、削除、選択、コピー、保存、Undo。
- 上から下・右から左への表示、実カーソルと表示位置の対応。
- IME 未確定文字の縦表示、文節の強調、確定・取消、候補位置の補正。
- Copilot の提案と Corfu のプレビューの縦表示、Corfu 候補一覧の位置補正。
- 上下左右の余白、文字間・列間、フォントの調整。
- 画面方向への移動キー設定。
- `C-v` / `M-v` 等による画面単位のページ移動、数値引数、短い最終ページとの往復。
- 対象ウィンドウへの表示限定、通常バッファとの分離、narrowing。

既定のページ移動はウィンドウに収まる縦列を基準とする。GUIの組版表示には固定字数・列数の紙面と見開きを追加する。これらは画面上の版面であり、PDF・印刷用の出力ページを生成するものではない。

既存テストの実行方法と過去の結果は `README.md` を参照する。追加モジュールの個別テストと、全体の回帰確認・GUI確認の結果は分けて記録する。

## 守る条件

1. 表示のために本文を書き換えない。縦書き約物、仮入力、候補、ルビの表示文字を保存内容に混入させない。
2. 実際の編集、IME の確定、補完の採用、Undo は既存の編集機構に任せる。
3. 通常バッファ、ミニバッファ、別ウィンドウ・別フレームへ設定や表示を漏らさない。
4. モード終了時に、表示、フック、キー、ローカル設定を復元する。
5. 元の文字位置、表示上の文字、カーソル、選択範囲の対応を保つ。
6. optional なパッケージや出力ツールがなくても、基本的な縦書き編集は使えるようにする。
7. GUI の座標や IME の操作性を、バッチテストの成功だけで検証済みとしない。

## 今回の実装構成と互換性

- `tategaki-highlight.el`: sourceのfaceを表示セルへ反映する。一般のoverlay文字列は取り込まない。
- `tategaki-typeset.el`: 原文位置を持つ表示単位、注記解析、禁則、段落キャッシュ、ページ内位置の参照。
- `tategaki-glyph.el`: SVGによる縦中横、欧文回転、ルビ、傍点・傍線、罫線の描画。
- `tategaki-typeset-view.el`: 組版モデルと表示セルをウィンドウ内へ配置する。
- `tategaki-annotations.el`: ルビ・縦中横・傍点/傍線の入力補助と注記表示の切り替え。
- `tategaki-manuscript.el`: 固定版面の設定、ページ情報・移動、キャッシュ付き字数集計、バッファ限定のモードライン。
- `tategaki.el`: 上記を既存の元バッファ編集、IME・補完、カーソル・マウス・ページ移動へ統合する。

`M-x tategaki-edit` は既定で従来の原文表示を使う。`M-x tategaki-typeset-edit` または現在のバッファで `(setq tategaki-typesetting t)` と再描画を行うと組版表示になる。`tategaki-toggle-annotations` は注記の組版表示と原文表示を切り替える。SVGがないGUI・TTYでは設定値を保持し、通常のウィンドウ追従型の原文表示へ戻る。固定版面・見開きもその代替表示では適用しない。

入力補助は `tategaki-insert-ruby`、`tategaki-edit-ruby`、`tategaki-insert-tcy`、`tategaki-add-emphasis`。注記の挿入・変更は通常の本文編集として保存・Undoの対象とする。表示の切り替えだけでは原文を変えない。

完全なJLReq準拠・UAX #29準拠・青空文庫の全注記対応は今回の範囲外。熟語ルビの高度な配置、全フォントの縦書きOpenType字形、あらゆる校正パッケージの専用表示は保証しない。

## 段階1: 毎日の執筆で困る表示と応答性を整える

### G01: 検索・校正の強調表示

**実装状況:** text propertyとoverlayのfaceを収集し、overlayの優先順位・包含関係を反映する。文字列置換は複製しない。複数文字をまとめたセルの一部に一致した場合はセル全体を強調し、検索・選択の原文範囲は保つ。専用GUIで実際のisearch、NSのIME表示、Copilot・Corfuの代表例を確認した。個別の校正パッケージ固有の表示は引き続き確認対象とする。

**方針:** 本文の文字位置にある表示属性を、縦書きの対応する表示セルへ反映する。検索処理そのものを置き換えない。初期対象は isearch、lazy-highlight、query-replace、本文の face とし、校正パッケージは個別に対応範囲を確認する。

- [x] 現在の選択範囲、IME、補完、検索結果、本文の装飾の優先順位を定義する。
- [x] 元の text property と overlay の face を取得し、表示対象の範囲だけに適用する。
- [x] 本文が変わらず overlay のみ変わった場合にも更新する。
- [x] 不明な `display`、`before-string`、`after-string` を無条件に複製しない。文字列を追加する機能は個別の連携対象とする。

**完了条件:** 縦列・ページをまたぐ検索結果と置換対象が見え、次の一致箇所へ移動できる。検索終了で強調が消え、本文と Undo に余分な変更がない。既存の選択・IME・補完の強調が壊れない。

### G02: 長文性能

**実装状況:** 改行区切りの段落解析と配置の再利用、変更した段落の解析、可視範囲の位置参照を実装した。統計は全文・章境界をキャッシュし、カーソル移動時は章を二分探索する。モデル単体・統計単体の時間を、画面の再描画まで含む入力遅延として扱わない。

**部分計測:** macOS / Emacs 31.1、バイトコンパイル済みモデル、単一段落の「文」の繰り返し、1列20字、中央への1字挿入を各1回測定。10万字は初回22.9ms・局所更新20.7ms、20万字は41.2ms・41.4ms。比較用の原文モデルの全配置はそれぞれ269ms・529msだった。GUI描画・face・SVG・IME等は測定外で、入力p95の実績ではない。再現関数 `tategaki-typeset-benchmark` は `test/tategaki-typeset-test.el` にあり、多数短段落の条件も含められる。一般の注記・結合文字・欧文回転を含む原稿への数値の一般化はしない。

**GUI入力計測:** 100桁×40行の専用フレーム、1列30字、100文字ごとに固有の漢字を含む生成本文を使用。単一段落と99文字＋改行の短段落について、入力からredisplayまで各20回測定した。p95は10万字で71.8ms / 58.3ms、20万字で91.8ms / 86.8ms。このfixtureでは10万字100ms以内の暫定目標を達成した。初回表示・ページ移動等を含む詳細と生データは[検証記録](vertical-typesetting-validation.md)・[計測結果](vertical-typesetting-timings.sexp)を参照する。

**方針:** 編集された段落と、その変更で影響を受ける配置を更新する。文字幅の計測、段落のレイアウト、可視ページの描画を分離してキャッシュする。ページ数の計算が入力を長時間止めないようにする。

- [x] 再現可能なモデル・統計ベンチマークとGUIの計測fixtureを用意し、入力から再描画までのp95を記録する。
- [x] フォント・余白・文字間・禁則設定等によるキャッシュ無効化条件を定義する。
- [x] 局所編集と、先頭への大きな貼り付け・全置換等の広い変更を分けて扱う。
- [x] キャッシュと全文再計算の結果が一致することを検証する。
- [ ] 注記・結合文字・欧文回転が大量に混在する長文の最悪ケースと、メモリ使用量の詳細を検証する。

**完了条件:** 同じ環境とテキストで変更前後を比較でき、通常の局所編集で全文の文字幅計測を繰り返さない。10万字の通常入力で再描画までの p95 を100ms以内とする暫定目標の評価は、上記fixtureの条件に限定する。20万字でも保存内容・位置対応・Undoを保ち、複雑な混在原稿や未測定環境への性能保証とは区別する。

## 段階4: ルビ・傍点・傍線

### G08・G09: 注記の表示と編集

**実装状況:** `｜親字《読み》`（ASCII `|` も可）、`漢字《読み》`、`［＃傍点］本文［＃傍点終わり］`、傍線・縦中横の同形式、および `本文［＃「本文」に傍点］` / 傍線を対象とする。読みは親文字ごとに均等配分する。未完・不正な記法は原文として残す。対応範囲はREADMEの表を正とし、青空文庫のその他の注記を推測で変換しない。

**方針:** 初期対象を青空文庫形式の限定した記法に絞り、対応記法を文書化する。文字列として入力した注記と、表示上の親文字・注記を対応させる。入力補助コマンドが記法を追加・削除する操作は、通常の本文編集として Undo 可能にする。

- [x] ルビの親文字範囲、読み、表示サイズ、配置をモデル化する。
- [x] 親文字を超える長いルビの均等配分と、列・ページ境界の扱いを定義する。
- [x] 記法を見せる編集表示と、組版した表示を切り替えられるようにする。
- [x] 未完成・不正な記法は原文表示に戻し、入力途中の文字を隠さない。
- [x] ルビ・傍点・傍線の描画と、選択・検索・IME表示の代表例を確認する。
- [ ] 多数の注記と選択・検索・IMEが同時に重なる長文の最悪ケースを確認する。

**完了条件:** 注記記法を保った保存・再読込ができる。親文字・読みをそれぞれ編集でき、注記は本文の文字数やページ計算で定義した扱いに従う。横書き表示との往復で記法が失われない。

## 段階5: ポメラ等を参考にした原稿管理

### G10・G11: 原稿用紙・固定版面・ページ情報

**実装状況:** `tategaki-manuscript-size` に `(20 . 20)` / `(40 . 30)` 等を指定し、`nil` はウィンドウ追従。GUI組版では小さい画面へ縮小し、論理的な字数・列数を保つ。見開きは2枚の表示で、任意の段組みとは別。`tategaki-goto-page` は文書の1始まりのページ指定、既存キーは画面移動を担う。EOF挿入位置だけの空ページは移動用の総ページ数に含め、本文配置枚数から除く。

- [x] ウィンドウに合わせた表示と、字数×列数で固定した原稿表示を分ける。
- [x] 20字×20列、40字×30列等をプリセットとして選べるようにする。
- [x] 原稿用紙の罫線、現在ページ・総ページ数、指定ページへの移動を追加する。
- [x] 小さいウィンドウでは縮小し、原稿の改ページ位置を変えない。
- [x] 固定版面の見開き表示を追加する。
- [ ] 任意の段組みを追加する。

**完了条件:** 画面ページと原稿ページの意味が明確で、文字の追加・削除に応じて原稿ページ数が更新される。既存の画面ページ移動を保つ。ズームと原稿の版面変更を区別できる。

### G12: 文字数・枚数・目標

**実装状況:** `tategaki-manuscript-status` でモードライン表示を切り替える。既定は水平空白を含み、改行・対応する注記記法・ルビの読みを除く。各規則は個別設定できる。文字数はEmacsの文字単位で、組版セル数ではない。全文/章/選択の集計をキャッシュし、目標値の変更は即座に残りへ反映する。章境界の自動認識はOrg見出し、MarkdownのATX見出し、`第3章`等。`outline-regexp`・独自regexp・無効化も選べる。アウトライン操作自体はG13の範囲として残す。

個別の `test/tategaki-manuscript-test.el` は29件成功。原文プロパティ・modified状態・Undo・narrowing・検索match-dataの保持、設定と目標の変更、キャッシュ再利用、EOF空ページ、ruby記法をまたぐページ移動、SVG非対応時のページ計算、未完/不正な注記と注記の部分選択、モードラインの優先配置と復元を含む。部分選択は前後の原文行を参照し、注記全体を含むときだけ記法を除く。これは組版編集全体のGUI確認の代わりではない。

標準のモードラインではバッファ名の直後に統計を置く。ページ・全文字数・400字換算・配置枚数・目標残りを優先し、選択と章の字数は後ろへ短いラベルで添える。独自のモードラインは内容を維持して統計の後ろへ置き、もともと非表示なら非表示を保つ。終了時には元の値とローカル変数の状態へ戻す。

統計だけの部分計測では、10万字に明示ルビ100個を含む本文で初回9.3ms・編集後14.7ms、キャッシュ済みモードライン評価1000回が合計2.36msだった。集計モジュールはバイトコンパイル済み、注記除去関数はソース、各1回、GUI描画と組版モデル作成は測定外。`tategaki-manuscript-benchmark` で再現できる。未注記部分は一括で扱い、字数集計のために全文を表示セルへ分解しない。

- [x] 全文、選択範囲、章の文字数を表示する。
- [x] 空白・改行・ルビ記法を数える規則を選択でき、既定値と表示の意味を文書化する。
- [x] 「文字数÷400による換算」と「原稿用紙へ配置した実際の枚数」を区別する。
- [x] 目標文字数と残り文字数は任意表示にする。
- [x] 統計をモードラインで優先表示し、非表示設定とモード終了時の復元を保つ。

**完了条件:** 同じ数え方なら通常の Emacs 側の集計と一致し、原稿用紙の空きマスを含む枚数との違いが説明される。集計で入力応答を悪化させない。

### G13・G14: アウトライン・入力支援

- [x] Org / outline 等を使い、見出し一覧からの移動を接続する。
- [ ] 折りたたみで非表示になった本文を縦書きレイヤーが再表示しないようにする。
- [ ] 章の並べ替え後に表示・ページ・文字数を更新する。
- [x] 自動一字下げ、会話文の字下げ調整、括弧補完を既存の入力設定と比較する。重複して挿入しない。
- [ ] 文書ごとの表示設定・再開位置は既存のローカル変数や保存機構を利用し、適用範囲を明確にする。

**完了条件:** 通常表示で行った章移動・折りたたみと縦表示の内容が一致する。設定を無効にすれば通常の入力に戻り、変更が他のバッファへ漏れない。

**追加実装:** `C-c C-o` で読み取り専用の見出し一覧を開く。編集後の一覧更新、現在章の追従、前後の見出し移動、補完による移動、一覧の階層折りたたみに対応。本文自体の折りたたみ・章の並べ替え専用UI・セッション復元は今回の対象に含めない。`tategaki-writing-mode` は新規入力と明示的整形だけを変更し、既存原稿の読み込み・貼り付けには適用しない。Smartparens等を使う場合はElectric Pair連携を無効化できる。

## 段階6: PDF・印刷・EPUBへの出力

## 段階7: 用途別の拡張

### G16: 脚本・台本

人物名、台詞、ト書き、シーン見出しの規則を定義し、原稿の構造を扱う既存モードとの連携を検討する。通常の文章編集を維持したまま、専用の体裁を選べるようにする。

**着手条件:** 実際に使う台本形式とサンプル原稿が決まっていること。

**完了条件:** 台詞等の挿入・削除・章移動後も位置と字下げが保たれ、元のテキストと出力結果を照合できる。

**追加実装:** 既定の簡易形式は `人物名：`、`　　「台詞」`、`　（ト書き）` の別段落。挿入コマンド、選択範囲の字下げ調整、人物名・台詞・ト書きごとの設定を用意した。全角空白を含む普通のテキストとして保存・Undoする。印刷時の独立した役名欄や、提出先固有の台本書式は未実装。

**専用モード:** `M-x tategaki-script-mode` はtext-mode派生のメジャーモードで、既定で組版縦書きを開始する。`○ 場所・時間` 等のシーン見出し、役割別face、人物名候補、人物名行末のRETから台詞入力、TABによる段落整形、シーンの前後移動・アウトライン・Imenuを提供する。開始時の自動整形はしない。既存の文章を専用形式へ揃える操作は明示的なコマンドに限定し、Undo可能。C-c C-cで横書きへ戻しても台本用の入力支援は継続し、text-modeへの切り替えで終了する。字下げは原文段落の先頭だけで、自動折り返し後の列への継続字下げは未実装。

## 検証と移行

各段階は「調査 → 小さな試作 → 実装 → 移行・互換性確認 → 自動テスト → 実画面確認 → 文書更新」で進める。

| 検証層 | 確認すること |
|---|---|
| レイアウト | 文字範囲、禁則、注記、ページ境界、再計算とキャッシュの一致 |
| 編集 | 挿入・削除・部分選択・コピー・保存・Undo・narrowing |
| GUI | 実カーソル、クリック、選択、文字拡大、リサイズ、余白・間隔、小さい画面 |
| 入力連携 | IME文節移動・確定・取消、Copilot全文・部分採用、Corfu選択・取消、候補ウィンドウ |
| 分離と後始末 | 同じ文書の別ウィンドウ、通常バッファ、モード終了、バッファ終了 |
| 性能 | 通常入力、大量貼り付け、先頭編集、全置換、ページ移動、メモリ量 |
| 出力 | PDF実ページ、抽出文字、EPUB構造と実機表示 |

- GUI試験は専用プロセス・専用バッファで行い、編集中のユーザー原稿に試験用の文字を入れない。
- Copilot連携試験では、表示・採用の試験に生成リクエストを必要としない。
- 既存設定の既定値と通常操作を保ち、組版・入力補助の新設定はバッファ単位で解除できるようにする。
- 検証結果には実行環境、対象テスト、成功・失敗・スキップ、未確認事項を記録する。
- 未確認の候補ウィンドウや出力結果を、内部座標のテストだけで確認済みにしない。

## 推奨する着手単位

最初の変更は **G01 の isearch / query-replace 表示対応**に限定する。原文の編集機構を維持したまま使い勝手を改善でき、以後の注記や校正表示にも役立つ。G02 の現状計測は独立して実施できる。

その後、複数文字をまとめる表示モデルを固め、禁則・縦中横、ルビ、原稿管理、出力の順に進める。描画方式の検証で制約が判明した場合は、対象機能の範囲と代替表示を計画へ反映する。
